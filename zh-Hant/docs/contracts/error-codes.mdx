請依穩定的錯誤碼做分支判斷，絕不要依訊息文字。

每一個失敗信封都會帶上同一張表中的某個 `E_*` 錯誤碼。錯誤碼只會新增，絕不會被改名或移除，唯一的例外是下面那次改為 `W_*` 的調整。錯誤碼旁邊的訊息屬於自由文案，任何版本都可能更動。

從 4.1.41 之後的版本起，警告會帶上 `W_*` 代碼，表示執行越過它繼續進行。錯誤與拒絕仍保留它們的 `E_*` 錯誤碼。見[警告碼](#警告碼)。

這張表隨 `extension-develop/contract/codes.json` 一起發布，參見 [結果信封](/zh-Hant/docs/contracts/result-envelope)。

## 用法

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_ARGS` | 缺少必要引數，或呼叫方式格式錯誤。從 4.2.0 之後的版本起，不帶指令的 `extension --output json` 會以一個 `usage` 影格回應它。 |
| `E_INVALID_OPTION` | 某個旗標或引數的值不在允許的集合內。 |
| `E_FLAG_VALUE_INVALID` | 某個旗標的值未通過驗證。 |
| `E_FLAG_NOT_SUPPORTED_HERE` | 該旗標存在，但不適用於這個指令或這個目標。 |
| `E_REMOVED_FLAG` | 該旗標已從 CLI 移除。 |
| `E_UNKNOWN_COMMAND` | 沒有子指令符合這個名稱。 |
| `E_NODE_VERSION` | 執行中的 Node 版本低於支援的最低版本。 |
| `E_COMMAND_UNSUPPORTED_FOR_TARGET` | 該指令不支援所要求的瀏覽器目標。 |
| `E_UNSUPPORTED_BROWSER` | 所要求的廠商不在支援的瀏覽器清單內。`extension.config.js` 中的 `commands.<cmd>.browser` 值也以同樣的方式檢查。從 4.2.0 起，空的 `--browser` 值或逗號清單中的空項目也以此代碼回應。 |
| `E_BROWSER_NOT_INSTALLABLE` | 該瀏覽器隨作業系統提供，CLI 無法安裝它。 |
| `E_PARENT_GONE` | `--parent-pid` 指定的宿主處理程序已死亡，開發伺服器因而自行結束。 |
| `E_REMOTE_URL_UNSUPPORTED` | 該操作不接受遠端 URL。 |

## 專案

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_PROJECT_NOT_FOUND` | 解析出的專案資料夾不存在。 |
| `E_PACKAGE_JSON_INVALID` | 從 4.2.0 之後的版本起。專案的 `package.json` 無法開啟、不是可解析的 JSON、以位元組順序標記開頭，或以 UTF-16 儲存。`dev`、`build`、`start` 與 `preview` 都會在編譯前以它回應。訊息會列出檔案。無法開啟的檔案以 "Make it a file this user can read, then run the command again." 結尾。解析錯誤以 "Fix the file, then run the command again." 結尾。編碼問題以 "Save the file as UTF-8 without a byte order mark, then run the command again." 結尾。 `extension doctor` 會因同一個檔案讓 `peer-rspack` 檢查失敗，並說明沒有檢查任何相依套件。 從 4.2.0 之後的版本起，當 `package.json` 是資料夾或特殊檔案而不是檔案時，它也會讓這些指令停止。那則訊息會列出路徑以及在那裡發現的內容。 |
| `E_CONFIG_LOAD` | `extension.config.js` 在載入時拋出例外，或匯出的不是物件。`dev`、`build`、`start` 與 `preview` 都以此代碼回應。正式建置遇到不合法的 [`perfBudgets`](/zh-Hant/docs/workflows/performance-playbook) 值時也以此代碼回應，從 4.2.0 起 `dev` 也是如此。從 4.2.0 之後的版本起，載入時拋出例外的 `vue.loader` 或 `svelte.loader` 選項檔也會讓建置以此代碼停止。 |
| `E_DEPENDENCY_INSTALL` | 安裝專案相依套件失敗。 |
| `E_OPTIONAL_DEP_UNRESOLVED` | 某個選用相依契約無法解析。 |
| `E_OPTIONAL_DEP_LOAD` | 某個選用相依已解析，但載入失敗。從 4.1.41 之後的版本起，專案中的副本在載入時拋出例外會讓執行停止。訊息會點名它的路徑與原因。不會改用其他安裝來代替。 |
| `E_OPTIONAL_DEP_UNKNOWN` | 未知的選用相依契約 id。 |
| `E_COMPANION_EXTENSION_PATH` | 解析出的根目錄下唯一的 manifest 屬於 `extensions/` 底下的某個搭配擴充功能。瀏覽器不載入它就開啟的搭配擴充功能條目，會以 `W_COMPANION_EXTENSION_PATH` 警告。 |
| `E_PROJECT_LAYOUT` | `public/` 中的某個檔案會覆寫建置產出的檔案，或 `extension.config.js` 中的某個 `include` 條目指向不存在的檔案，或指向擴充功能之外的輸出路徑。 |
| `E_MANIFEST_IN_PUBLIC` | `manifest.json` 被放在 `public/` 底下。 |
| `E_FOLDER_UNREADABLE` | `pages/` 或 `scripts/` 裡的某個資料夾無法讀取，所以建置無法列出它的入口。從 4.2.0 之後的版本起。 |
| `E_ENV_FILE_UNREADABLE` | 建置要讀取的某個 env 檔案是一個資料夾或無法讀取。從 4.2.0 起。 |
| `E_RUNTIME_NOT_FOUND` | extension-develop 執行階段遺失、未編譯，或與 CLI 版本不同。從 4.2.0 之後的版本起，它也涵蓋載入時擲出錯誤的已安裝引擎，例如安裝漏掉了原生繫結的引擎。訊息會列出引擎資料夾、原因與重新安裝的指令。 |

## Manifest

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_MANIFEST_NOT_FOUND` | 解析出的根目錄下沒有 `manifest.json`。 |
| `E_MANIFEST_INVALID` | manifest 不是可解析的 JSON，或不是 WebExtension manifest。 |

## 編譯

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_FIRST_COMPILE` | 工作階段的第一次編譯失敗，因此什麼都沒有載入。 |
| `E_COMPILE` | 編譯結束時帶有錯誤。 |
| `E_COMPILE_FATAL` | 編譯器本身失敗，或回傳了無法使用的統計資料。從 4.1.41 之後的版本起，它也涵蓋在建立編譯器時拋出例外的外掛，例如在它的 `apply` 中。 |
| `E_MODULE_NOT_FOUND` | 某個模組識別字無法解析。 |
| `E_ENTRY_NOT_FOUND` | 某個 manifest、HTML 或 JSON 進入點指向不存在或未被打包的檔案。 |
| `E_ASSET_MISSING` | 某個圖示、靜態資源或 JSON 相依不存在或未被打包。 |
| `E_SCRIPT_DEP_MISSING` | 某個執行階段指令稿相依無法被追蹤到。 |
| `E_RESERVED_FOLDER` | 違反了保留的 `scripts/` 資料夾結構。 |
| `E_CSS_PARSE` | 某個樣式表解析失敗。 |
| `E_CSS_PREPROCESSOR_MISSING` | 要求了某個 CSS 前處理器，但無法解析到它。 |
| `E_CSS_DEAD_REF` | CSS 中的某個 `url()` 或 `@import` 指向不存在或未被打包的檔案。 |
| `E_LOCALES_LAYOUT` | `_locales` 的結構或 `messages.json` 不合法。 |
| `E_WAR_INVALID` | `web_accessible_resources` 的結構或比對樣式遭到拒絕。 |
| `E_BACKGROUND_REQUIRED` | 從 4.2.0 之後的版本起保留，不再產生。缺少的 background 腳本在 `dev` 與正式建置中都回報 `E_ENTRY_NOT_FOUND`。4.2.0 及之前，background chunk 缺少時由重新載入執行階段拋出。 |
| `E_CONTENT_SCRIPT_SYNTAX` | 某個 content script 解析失敗。 |
| `E_INLINE_SCRIPT_SYNTAX` | 從 4.2.0 之後的版本起。HTML 檔案中的內嵌指令稿在未加引號的佔位符被填入 env 值之後不再能剖析。 |
| `E_PERF_BUDGET` | 某個資源超出了它的大小預算，且 `perfBudgets.onExceed` 為 `'error'`，因此建置失敗。沒有這個設定時，超出預算只會以 `W_PERF_BUDGET` 警告。見[效能預算](/zh-Hant/docs/workflows/performance-playbook)。 |
| `E_THEME_INVALID` | 某個主題顏色或色調不是 Chromium 瀏覽器能載入的數字陣列，而建置無法精確轉換它。 |
| `E_DEV_SESSION_DIST_SHARED` | 某次建置會寫入一個正在執行的開發工作階段所服務的輸出資料夾，因此遭到拒絕。傳入 `--out-dir` 以在旁邊建置。 |
| `E_OUTPUT_NOT_WRITABLE` | 建置無法寫入輸出資料夾：資料夾不可寫入，或 `manifest.json` 無法寫入其中。從 4.2.0 之後的版本起，唯讀的輸出資料夾在建置時也以它回應。訊息會列出資料夾與原因（`EACCES`、`EPERM` 或 `EROFS`），並請你讓資料夾可寫入，或以 `--out-dir` 另選一個。 |
| `E_JSON_INVALID` | manifest 指向的某個 JSON 檔案無法解析，或它的 `declarativeNetRequest` 規則集或受管理儲存結構描述的形狀遭到瀏覽器拒絕。 |
| `E_ASSET_IMPORT_SHAPE` | 以 `import * as` 匯入的資源會被讀成檔案的值，也就是預設匯出。 |
| `E_ZIP_SKIPPED` | 打包因某個已說明的原因被略過。 |

`E_COMPILE` 和 `E_FIRST_COMPILE` 是編譯失敗時的頂層錯誤碼。上表中有十三列會出現在該影格的 `error.details` 裡，每個錯誤一個：`E_MODULE_NOT_FOUND`、`E_CONTENT_SCRIPT_SYNTAX`、`E_INLINE_SCRIPT_SYNTAX`、`E_CSS_PARSE`、`E_ENTRY_NOT_FOUND`、`E_ASSET_MISSING`、`E_SCRIPT_DEP_MISSING`、`E_RESERVED_FOLDER`、`E_CSS_PREPROCESSOR_MISSING`、`E_CSS_DEAD_REF`、`E_LOCALES_LAYOUT`、`E_WAR_INVALID` 和 `E_PERF_BUDGET`。4.2.0 及之前，`E_BACKGROUND_REQUIRED` 也可能出現在這裡。`details` 中的警告帶有 `severity: "warning"` 與一個 `W_*` 代碼。成功建置的 `warnings` 字串開頭也是同樣的 `W_CODE: ` 前綴。見[編譯診斷](/zh-Hant/docs/contracts/result-envelope)。

## 遠端專案與網路

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_REMOTE_FETCH_TIMEOUT` | 某次遠端擷取超過了它的逾時時間。 |
| `E_REMOTE_DOWNLOAD` | 遠端擴充功能無法下載或無法寫入磁碟，例如連線遭拒或 HTTP 錯誤。訊息為 `Couldn't download the ZIP file or write it to disk.` |
| `E_REMOTE_ZIP_INVALID` | 該遠端 URL 回傳的並不是 ZIP、回傳的封存檔已損毀無法解開，或回傳的封存檔含有位於其資料夾之外的條目。最後這種封存檔會在寫入任何內容之前遭拒，訊息會點名該條目，也不會建議重試。 |
| `E_LOCAL_ZIP_NOT_FOUND` | 被參照的本機 zip 遺失，或根本不是 zip。 |
| `E_PROJECT_DOWNLOAD_EMPTY` | 下載成功，但解壓出的資料夾並不存在。 |
| `E_NETWORK` | 某個網路請求失敗或逾時。 |

## 瀏覽器執行檔與啟動

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_BROWSER_NOT_FOUND` | 所要求的廠商沒有已安裝的執行檔。 |
| `E_BROWSER_BINARY_REQUIRED` | `-based` 目標需要明確的執行檔路徑。 |
| `E_BROWSER_BINARY_INVALID` | 固定的 `--chromium-binary` 或 `--gecko-binary` 不存在、不是可執行檔，或在 10 秒內沒有回應版本探測。從 4.1.39 之後的版本起，`FIREFOX_BINARY` 這類執行檔變數指向不存在或不可執行的路徑時，也以同樣的方式失敗。`start`、`dev` 與 `preview` 都以狀態 `usage` 回應它。 |
| `E_BROWSER_LAUNCH` | 瀏覽器處理程序無法產生，或在啟動時就死掉了。 |
| `E_BROWSER_EXITED` | 已啟動的瀏覽器結束了，而伺服器仍在執行。 |
| `E_BROWSER_START_TIMEOUT` | 瀏覽器始終沒有送出啟動訊號。 |
| `E_PROFILE_LOCKED` | 該設定檔目錄被另一個瀏覽器處理程序占用。 |
| `E_INSTANCE_AMBIGUOUS` | 有多個存活的實例符合所要求的 id。 |
| `E_BROWSER_DOWNLOAD` | 下載或安裝瀏覽器失敗。從 4.1.41 之後的版本起，缺少套件執行器時改為回傳 `E_BROWSER_INSTALLER_NOT_FOUND`。從 4.2.0 之後的版本起，它也涵蓋存在但無法啟動的套件執行器，而類型未知的安裝故障改為回傳 `E_INTERNAL`。 |
| `E_BROWSER_INSTALL_PRIVILEGE` | 這次安裝需要一個互動式的特權工作階段。 |
| `E_BROWSER_UNINSTALL` | 移除已安裝的瀏覽器失敗。 |
| `E_BROWSER_INSTALL_TIMEOUT` | 到了安裝逾時時間，瀏覽器安裝程式仍在執行，因此被停止。 |
| `E_BROWSER_INSTALL_BUSY` | 整段等待之後，同一個瀏覽器的另一次安裝仍在執行，因此這次安裝從未開始。 |
| `E_BROWSER_CACHE_NOT_WRITABLE` | 瀏覽器快取根目錄是一個檔案、無法建立，或無法寫入。 |
| `E_BROWSER_FOLDER_FOREIGN` | 快取中的瀏覽器資料夾含有安裝程式從不寫入的檔案，因此安裝沒有動它。 |
| `E_BROWSER_INSTALLER_NOT_FOUND` | 這台機器上沒有用來安裝瀏覽器的套件執行器。 |

## 瀏覽器執行階段

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_EXTENSION_LOAD_REFUSED` | 瀏覽器拒絕了這個未封裝的擴充功能。從 4.1.41 之後的版本開始，`start`、`preview`、`dev --wait`、`start --wait`、act 指令以及 `dev --output json` 的串流會以狀態 `load-refused` 和結束代碼 `1` 回答它。`doctor --output json` 以狀態 `unhealthy` 帶上它。 |

## 除錯協定

| 錯誤碼 | 意義 |
| ---- | ------- |
| `E_BROWSER_CONNECT` | 無法開啟除錯連線，例如 Firefox 的除錯器始終沒有回應。 |
| `E_BROWSER_CONNECTION_CLOSED` | 除錯 socket 在工作階段中途關閉。 |
| `E_CDP_NOT_CONNECTED` | 在沒有存活 CDP 傳輸的情況下發出了某個操作。 |
| `E_CDP_TIMEOUT` | 某個 CDP 指令或 load 事件逾時。 |
| `E_CDP_OP_FAILED` | 透過 CDP 執行的某個擴充功能操作失敗。 |
| `E_EXTENSION_ID_UNKNOWN` | 無法透過 CDP 判定擴充功能 id。 |
| `E_RDP_PROTOCOL` | 出現格式錯誤或非預期的 RDP 交換。 |

從 4.1.41 之後的版本起，啟動後發生、而工作階段仍保持就緒的 CDP 故障，改帶警告名稱：`W_CDP_NOT_CONNECTED`、`W_CDP_TIMEOUT`、`W_CDP_OP_FAILED`、`W_BROWSER_CONNECTION_CLOSED` 或 `W_EXTENSION_ID_UNKNOWN`。`ready.json` 的 `cdpFaultCode` 也一樣。

## 開發伺服器

| ---- | ------- |
| `E_DEV_SERVER_START` | 開發伺服器啟動失敗。 |
| `E_PORT_UNAVAILABLE` | 在所要求的埠號附近找不到可綁定的空閒埠號。 |

| ---- | ---- | ------- |
| `E_PREVIEW_NO_DIST` | preview | 解析出的輸出路徑下沒有未封裝的擴充功能。 |
| `E_SAFARI_TOOLCHAIN` | safari | Safari 工具鏈不可用，或某次呼叫失敗。 |
| `E_SAFARI_UI` | safari | 讀取或操作 Safari 本身的設定或工具列失敗。 |
| `E_ACCESSIBILITY_DENIED` | safari | macOS 尚未授予宿主應用程式輔助使用權限，因此無法讀取或操作 Safari 本身的 UI。 |
| `E_PUBLISH_REJECTED` | publish | 平台拒絕了這次上傳。 |
| `E_AUTH_REQUIRED` | publish | 該操作需要一個驗證權杖，但它並不存在。 |
| `E_TELEMETRY_WRITE` | telemetry | 無法寫入遙測同意檔案。 |
| `E_DOCTOR_CHECKS_FAILED` | doctor | 有一項或多項 doctor 檢查回報失敗。 |
| `E_INTERRUPTED` | internal | 該操作在完成之前被中斷。 |
| `E_INTERNAL` | internal | 一個非預期的錯誤傳到了最上層的錯誤匯集點。 |

## 警告碼

從 4.1.41 之後的版本起，每個帶代碼的警告都會帶上 `W_*` 代碼。它出現在 `severity: "warning"` 的 `error.details` 條目上、每個 `warnings` 字串的開頭，以及 `ready.json` 的 `cdpFaultCode` 中。既可能失敗也可能警告的類別，在兩個前綴下各有一個詞幹相同的代碼，例如 `E_PERF_BUDGET` 與 `W_PERF_BUDGET`。

4.1.41 及更早的版本以詞幹相同的 `E_*` 名稱回報其中許多警告，例如 `E_CSS_DEAD_REF`。依代碼比對警告的指令稿，請改讀 `W_` 而不是 `E_`。沒有任何別名。

| 代碼 | 意義 |
| ---- | ------- |
| `W_MANAGED_DEP_CONFLICT` | 專案宣告了一個由工具鏈託管的套件。 |
| `W_TYPES_EMIT` | 寫出 `extension-env.d.ts` 失敗。 |
| `W_MODULE_NOT_FOUND` | 某個模組識別字無法解析，建置在沒有它的情況下繼續。 |
| `W_ENTRY_NOT_FOUND` | 某個 manifest、HTML 或 JSON 進入點指向不存在或未被打包的檔案。 |
| `W_ASSET_MISSING` | 某個圖示、靜態資源或 JSON 相依不存在或未被打包。 |
| `W_SCRIPT_DEP_MISSING` | 某個指令稿在執行階段載入的檔案不在建置中、以原始碼的寫法被點名，或無法編譯。從 4.2.0 之後的版本起，指令稿裡的 `new URL("...", import.meta.url)` 參照若既不指向指令稿旁的檔案，也不指向已安裝的套件，也會回報它。建置會照原樣保留這個位址，`EXTENSION_STRICT_REFS=true` 會把它變成 `E_SCRIPT_DEP_MISSING`。 |
| `W_CSS_PARSE` | 某個樣式表解析失敗，或者壓縮器丟掉了一條規則，樣式表照原樣發布。 |
| `W_CSS_PREPROCESSOR_MISSING` | 要求了某個 CSS 前處理器，但無法解析到它。 |
| `W_CSS_DEAD_REF` | CSS 中的某個 `url()` 或 `@import` 指向不存在或未被打包的檔案。 |
| `W_POLYFILL_NOT_FOUND` | 要求了 `webextension-polyfill`，但它並不存在。從 4.2.0 之後的版本起，它列在首次編譯的警告中，每種輸出格式都從那裡讀取。 |
| `W_LOCALES_LAYOUT` | `_locales` 的結構或 `messages.json` 不合法。 |
| `W_PROD_LOOPBACK_ORIGIN` | 正式版 manifest 點名了某個 loopback 來源（`localhost`、`127.0.0.0/8`、`[::1]` 或 `0.0.0.0`），商店審查者會把它看成未說明的主機存取。 |
| `W_NO_ENTRYPOINTS` | 這次編譯產出了零個進入點。 |
| `W_REMOTE_RESOURCE_BLOCKED` | 某個遠端指令稿或樣式表被擴充功能 CSP 封鎖。 |
| `W_PERF_BUDGET` | 某個資源超出了它的大小預算。 |
| `W_ENV_NO_MATCH` | 沒有任何 `.env` 檔案符合目前模式。 |
| `W_LAUNCH_SKIPPED_COMPILE_ERRORS` | 因為編譯失敗，所以沒有啟動瀏覽器。 |
| `W_UNINSTALL_NOOP` | 沒有可以移除的東西。 |
| `W_PORT_IN_USE` | 所要求的埠號已被占用，已自動改用其他埠號。 |
| `W_LOGS_STREAM_GAP` | follow 串流掉了部分事件。 |
| `W_MANIFEST_INVALID` | 某個 manifest 欄位的形狀是瀏覽器拒絕載入的，建置已修正或捨棄它。 |
| `W_WAR_INVALID` | 某個 `web_accessible_resources` 樣式離開了擴充功能根目錄，因此不會公開任何檔案。從 4.2.0 之後的版本起，它也標記以 `url()` 指向建置不會交付之檔案的已列出樣式表。 |
| `W_RESERVED_FOLDER` | `scripts/` 中的某個檔案只被另一個檔案匯入，而該資料夾中的每個檔案都會各自建置成一個進入點。 |
| `W_INTERNAL` | 某個建置步驟遇到非預期的輸出並繼續進行。工具鏈需要更新。 |
| `W_RESTART_REQUIRED` | 執行中的開發工作階段只在啟動時讀取的某個檔案變更了，因此變更會在重新啟動後生效。 |
| `W_RELOAD_NOT_APPLIED` | 從 4.2.0 之後的版本起，印在 `dev` 工作階段的瀏覽器主控台中：重新載入或熱更新無法在那裡生效，所以開啟的頁面或擴充功能保留它已有的建置。 |
| `W_CONTENT_SCRIPT_NOT_INJECTED` | 從 4.2.0 之後的版本起，印在 `dev` 工作階段的背景主控台中：背景無法回應要求其 content script 的頁面，所以該頁面在沒有它的情況下執行。 |
| `W_DEV_SERVER_SOCKET` | 從 4.2.0 之後的版本起，印在 `dev` 工作階段中擴充功能頁面的主控台裡：與開發伺服器的 socket 失敗，所以修改要在頁面重新載入後才顯示。 |
| `W_CONTENT_SCRIPT_CLEANUP` | 從 4.2.0 之後的版本起，印在頁面主控台中：content script 回傳的清理函式擲出錯誤，所以指令稿留在頁面上的內容可能會保留。 |
| `W_CONTENT_SCRIPT_MOUNT` | 從 4.2.0 之後的版本起，印在頁面主控台中：content script 的預設匯出在執行時擲出錯誤。 |
| `W_JSON_INVALID` | 某個 `declarativeNetRequest` 規則集可以解析，但含有可能不會照寫法運作的規則，或含有 Chrome 拒絕而 Firefox 會載入的規則。 |
| `W_PROJECT_LAYOUT` | 某個 `public/` 資料夾放錯位置或被另一個遮蔽，或 `extension.config.js` 中的某個 `exclude` 條目指向不存在的檔案。從 4.2.0 之後的版本起，它也涵蓋大小寫不對的 `public/` 資料夾，以及被入口遮蔽的 `public/` 檔案。它還涵蓋任何建置都不讀取的 `Pages/` 或 `Scripts/` 資料夾，以及 `pages/` 或 `scripts/` 中建置為同一個入口名稱的兩個檔案。 |
| `W_MANIFEST_COMPAT` | manifest 使用了目標瀏覽器會忽略或正在淘汰的版本、鍵或主機權限樣式。 從 4.2.0 之後的版本起，它也會標記權限項目上的瀏覽器前綴，建置會為每個瀏覽器解析該前綴。 |
| `W_STORE_READINESS` | manifest 可以建置並載入，但商店會照現在的寫法拒絕或標記它。 |
| `W_PERMISSION_MISMATCH` | 程式碼使用的 API 或連線的主機，沒有被 manifest 權限以程式碼需要的方式涵蓋。 |
| `W_API_UNSUPPORTED` | 程式碼呼叫了目標瀏覽器沒有的擴充功能 API，或某種 API 形式。 |
| `W_WAR_EXPOSURE` | 某個指令稿點名的檔案無法透過 `web_accessible_resources` 存取，或建置公開它的範圍比 manifest 列出的更廣。 |
| `W_CSS_NOT_APPLIED` | 某個樣式表匯入或 `url()` 保留在輸出中，但瀏覽器不會在它所在的位置套用它。從 4.2.0 之後的版本起，它也標記沒有執行的 PostCSS 或樣式表設定步驟，例如無法載入的 PostCSS 設定。4.2.0 及之前的版本給這些警告的是 `W_RESTART_REQUIRED`。 |
| `W_ENV_SECRET_PUBLIC` | 某個 `EXTENSION_PUBLIC_` 變數的名稱看起來像機密，而它的值會被寫入建置後的程式碼。 |
| `W_BUILD_CONSTANT_UNDEFINED` | 某個指令稿讀取了沒有任何東西定義的建置常數，因此它在載入時會拋出例外。 |
| `W_SCRIPT_WORLD_UNKNOWN` | 某個指令稿在執行階段以建置無法讀出的 world 註冊，因此被當成隔離 world 的指令稿。 |
| `W_ENV_DEFINE_WRITTEN` | 專案程式碼寫入了建置會取代為其值的 env 名稱，所以這個名稱的點號讀取保留建置時的值。 |
| `W_ENV_NAME_RESERVED` | 某個 `.env` 檔案設定了建置為它所編譯的瀏覽器或模式保留的名稱，因此檔案中的值被忽略。 |
| `W_ENV_ASSET_NOT_UTF8` | 某個輸出的 `.json` 或 `.html` 檔案含有 `$EXTENSION_` 佔位符，但不是 UTF-8 文字，所以它以原樣的位元組發布，佔位符保持原樣。從 4.2.0 之後的版本起。 |
| `W_COMPANION_EXTENSION_PATH` | 某個搭配擴充功能條目通往專案之外、不是未封裝的擴充功能資料夾，或指向不存在的資料夾，因此瀏覽器在沒有它的情況下開啟。 |
| `W_CDP_NOT_CONNECTED` | 某個 `dev`、`start` 或 `preview` 工作階段在沒有存活 CDP 傳輸的情況下啟動，並保持就緒。重新載入與 HMR 無法連上。 |
| `W_CDP_TIMEOUT` | 啟動後某個 CDP 指令或載入逾時，而 `dev`、`start` 或 `preview` 工作階段保持就緒。重新載入與 HMR 無法連上。 |
| `W_CDP_OP_FAILED` | 啟動後透過 CDP 執行的某個擴充功能操作失敗，而 `dev`、`start` 或 `preview` 工作階段保持就緒。重新載入與 HMR 無法連上。除了另外四個有自己警告名稱的類別，其他類別的故障也以這個代碼回報。 |
| `W_BROWSER_CONNECTION_CLOSED` | 啟動後除錯 socket 關閉，而 `dev`、`start` 或 `preview` 工作階段保持就緒。重新載入與 HMR 無法連上。 |
| `W_EXTENSION_ID_UNKNOWN` | 啟動後無法透過 CDP 判定擴充功能 id，而 `dev`、`start` 或 `preview` 工作階段保持就緒。重新載入與 HMR 無法連上。 |

## 折疊名稱與舊名稱

`codes.json` 在這張表之外還帶了兩份額外對應：

- `folded` 把較細的清單名稱對應到已發布的家族錯誤碼上。例如 `E_ARG_REQUIRED` 會折疊為 `E_ARGS`，`E_BROWSER_NOT_INSTALLED` 會折疊為 `E_BROWSER_NOT_FOUND`。
- 十一個只曾標示警告的 `E_*` 名稱會折疊為它們的 `W_*` 名稱，例如 `E_PORT_IN_USE`。現在已沒有任何東西回報它們。
- `legacy` 把信封出現之前的三種命名慣例對應到這張表上：`ready.json` 的 snake_case 錯誤碼（`profile_locked` 對應 `E_PROFILE_LOCKED`）、PascalCase 的錯誤名稱（`TargetNotFound` 對應 `E_TARGET_NOT_FOUND`），以及 kebab-case 的 doctor 檢查項 id（`eval-token` 對應 `E_TOKEN_MISSING`）。

如果你的取用端遇到表中沒有的名稱，請先透過這些對應解析出來，再做分支判斷。
