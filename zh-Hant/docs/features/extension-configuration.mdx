用一份設定檔同時設定瀏覽器預設值、指令行為與 bundler 客製化。

跨團隊共用瀏覽器預設、指令選項與建置設定，不再重複輸入 CLI 旗標。Extension.js 會從專案根目錄讀取 `extension.config.js`（或 `.mjs` / `.cjs`），並套用到每個指令與 bundler。

## 運作方式

在專案根目錄（通常和 `package.json` 同層）加上 `extension.config.js`。

支援的檔名：

- `extension.config.js`
- `extension.config.mjs`
- `extension.config.cjs`

頂層的鍵：

| 鍵                  | 說明                                                          |
| ------------------- | ------------------------------------------------------------- |
| `browser`           | 依瀏覽器目標分鍵的瀏覽器專屬預設值。                          |
| `commands`          | 各指令的預設值（`dev`、`start`、`preview`、`build`）。        |
| `extensions`        | 跨指令套用的附屬擴充功能（僅載入）。                          |
| `transpilePackages` | 打包前要先編譯的套件（在 monorepo／workspace 設定中很實用）。 |
| `perfBudgets`       | 依類別設定的資源體積預算（位元組），可依瀏覽器與指令覆寫。 |
| `define`            | 內嵌進每個 bundle 的編譯期常數，可依瀏覽器與指令覆寫。        |
| `folders`           | 特殊資料夾所在的位置，或用 `false` 關掉其中一個，可依瀏覽器與依指令覆寫。 |
| `config`            | 用來擴充／覆寫產生出的 Rspack 設定的 hook。會收到目標瀏覽器、模式與命令。 |
| `configResolved`    | 在 Rspack 設定最終確定、所有 loader 規則都已掛上之後執行的 hook。 |

### 型別安全的設定

Extension.js 從 `extension` 套件匯出 `FileConfig` 型別，讓編輯器能對你的設定自動完成與型別檢查。用 JSDoc `@type` 標籤標註匯出——它可在 `extension.config.js`、`.mjs` 與 `.cjs` 中運作,且不需要建置步驟：

```js
/** @type {import('extension').FileConfig} */
export default {
  browser: {
    chrome: { profile: "path/to/profile" },
  },
};
```

### 設定檔的環境載入

`extension.config.*` 在 Node 中執行，應該從 `process.env.*` 讀取值。

- Extension.js 在評估 `extension.config.*` 之前，會依由弱到強的順序預先載入 env 檔：`.env.defaults`、`.env`、`.env.local`、`.env.development`。每個存在的檔案都會載入，而 shell 匯出的變數永遠優先。
- 它會先檢查專案資料夾。
- 在 monorepo 中，若 Extension.js 找不到專案本地的 `.env*`，會 fallback 到最近的 workspace 根目錄，也就是包含 `pnpm-workspace.yaml` 的資料夾。
- 比起在設定檔中匯入 `dotenv`，建議優先使用內建的 env 預載。

### 瀏覽器設定

需要為每個目標設定不同的瀏覽器預設值？使用 `browser`：

```js
export default {
  browser: {
    chrome: {
      profile: "path/to/profile",
      preferences: { darkMode: true },
      browserFlags: ["--disable-web-security"],
      excludeBrowserFlags: ["--mute-audio"],
    },
    "chromium-based": {
      chromiumBinary: "/path/to/brave-or-other-chromium-binary",
    },
    firefox: {
      geckoBinary: "/path/to/firefox",
    },
  },
};
```

支援的瀏覽器鍵包括：`chrome`、`edge`、`firefox`、`chromium`、`chromium-based`、`gecko-based`、`firefox-based`。

常用的瀏覽器欄位：

- `profile`、`persistProfile`
- `preferences`
- `browserFlags`、`excludeBrowserFlags`
- `chromiumBinary`、`geckoBinary`
- `extensions`（僅載入的附屬擴充功能）

#### 瀏覽器目標能力

| 鍵                    | 作用                                            |
| --------------------- | ----------------------------------------------- |
| `profile`             | 設定瀏覽器啟動時使用的 profile 路徑（或行為）。 |
| `persistProfile`      | 在多次執行間沿用 profile 資料。                 |
| `keepProfileChanges`  | 在多次執行間保留受管 profile 及其變更。         |
| `copyFromProfile`     | 以既有 profile 目錄的副本來初始化受管 profile。 |
| `preferences`         | 套用瀏覽器偏好設定覆寫。                        |
| `browserFlags`        | 在瀏覽器程序啟動時加入旗標。                    |
| `excludeBrowserFlags` | 移除不想使用的預設啟動旗標。                    |
| `chromiumBinary`      | 使用自訂的 Chromium 系二進位檔路徑。            |
| `geckoBinary`         | 使用自訂的 Gecko/Firefox 二進位檔路徑。         |
| `extensions`          | 與主擴充功能一起載入附屬擴充功能。              |
| `transpilePackages`   | 為此瀏覽器編譯的套件。優先於頂層清單。                 |
| `perfBudgets`         | 此瀏覽器的資源預算。優先於頂層預算。                   |
| `define`              | 此瀏覽器的常數。附加到頂層對應表上，並覆寫重複的鍵。   |
| `folders`             | 此瀏覽器的特殊資料夾位置。整個取代頂層的 `folders` 物件。 |

### 指令設定

用 `commands` 定義每個指令的預設值：

```js
export default {
  transpilePackages: ["@workspace/ui"],
  commands: {
    dev: {
      browser: "chrome",
      polyfill: true,
      logLevel: "info",
      persistProfile: true,
      browserFlags: ["--headless=new"],
      extensions: { dir: "./extensions" },
    },
    start: {
      browser: "firefox",
    },
    preview: {
      browser: "edge",
      noBrowser: false,
    },
    build: {
      browser: "chrome",
      zip: true,
      zipSource: true,
      zipFilename: "my-extension.zip",
      transpilePackages: ["@workspace/ui", "@workspace/icons"],
    },
  },
};
```

注意事項：

- `extensions`、`transpilePackages` 與 `perfBudgets` 在每個指令上都依由弱到強分層：頂層，接著是 `browser.<vendor>`，接著是 `commands.<cmd>`，最後是 CLI 旗標。
- `define` 在同樣的層上逐鍵合併：頂層，接著是 `browser.<vendor>`，接著是 `dev`、`start` 與 `build` 上的 `commands.<cmd>`。
- `folders` 從不逐鍵合併。`browser.<vendor>.folders` 取代頂層物件，`dev`、`start` 與 `build` 上的 `commands.<cmd>.folders` 則同時取代這兩者。
- `commands.build.browser`、`commands.start.browser` 與 `commands.preview.browser` 決定這些指令的目標瀏覽器。`--browser` 旗標仍然優先。
- `start` 指令會在內部依序執行 `build` 與 `preview`。Extension.js 會套用 `commands.start` 中的設定，包括 `profile`、`browserFlags` 與 `startingUrl` 等瀏覽器啟動選項。你也可以把建置專屬的設定放在 `commands.build`。

#### 指令共用能力

| 鍵                    | 適用於                             | 作用                                                       |
| --------------------- | ---------------------------------- | ---------------------------------------------------------- |
| `browser`             | `dev`、`start`、`preview`、`build` | 設定瀏覽器或瀏覽器家族目標。`--browser` 旗標優先。         |
| `profile`             | `dev`、`start`、`preview`          | 設定瀏覽器 profile 路徑／行為。                            |
| `persistProfile`      | `dev`、`start`、`preview`          | 在多次執行間沿用瀏覽器 profile 資料。                      |
| `chromiumBinary`      | `dev`、`start`、`preview`          | 使用自訂的 Chromium 系二進位檔。                           |
| `geckoBinary`         | `dev`、`start`、`preview`          | 使用自訂的 Gecko 系二進位檔。                              |
| `polyfill`            | `dev`、`start`、`build`            | 在相關情境啟用相容性 polyfill 行為。                       |
| `preferences`         | `dev`、`start`、`preview`          | 套用瀏覽器偏好設定覆寫。                                   |
| `browserFlags`        | `dev`、`start`、`preview`          | 在瀏覽器程序啟動時加入旗標。                               |
| `excludeBrowserFlags` | `dev`、`start`、`preview`          | 移除不想使用的預設啟動旗標。                               |
| `startingUrl`         | `dev`、`start`、`preview`          | 在瀏覽器啟動時開啟指定 URL。                               |
| `port`                | `dev`、`start`、`preview`          | 設定 runner／DevTools 連接埠。                             |
| `host`                | `dev`、`start`、`preview`          | 設定開發伺服器主機。Docker／dev container 請用 `0.0.0.0`。 |
| `publicHost`          | `dev`、`start`、`preview`          | 設定瀏覽器為 HMR 與重新載入橋接撥號的可連線主機。`start` 與 `preview` 為了保持一致而接受它，但會忽略。 |
| `allowedHosts`        | `dev`                              | 開發伺服器額外回應的 `Host` 名稱，陣列或逗號分隔的字串。前導的點允許所有子網域。 |
| `noBrowser`           | `dev`、`start`、`preview`          | 停用瀏覽器啟動（`commands.<cmd>.noBrowser`）。             |
| `extensions`          | `dev`、`start`、`preview`、`build` | 載入附屬擴充功能（或擴充功能清單）。                       |
| `folders`             | `dev`、`start`、`build`            | 此指令的特殊資料夾位置。取代頂層與依瀏覽器設定的 `folders`。 |
| `install`             | `dev`、`start`、`build`            | 執行前先安裝缺少的依賴項。                                 |
| `transpilePackages`   | `dev`、`start`、`preview`、`build` | 編譯指定的 workspace／外部套件。                           |

| 鍵            | 作用                                            |
| ------------- | ----------------------------------------------- |
| `zip`         | 產生封裝後的 zip 產物。                         |
| `zipSource`   | 為審查／合規流程額外產出原始碼 bundle／封存檔。 |
| `zipFilename` | 同時命名兩個壓縮檔，與 `--zip-filename` 相同。發佈壓縮檔一定會附加瀏覽器名稱，原始碼壓縮檔則是不帶瀏覽器的 `<name>-source.zip`。 |
| `silent`      | 減少建置記錄輸出。                              |
| `perfBudgets` | 為建置覆寫頂層依類別設定的資源預算。            |

#### `dev` 指令能力

| 鍵                   | 作用                                                                       |
| -------------------- | -------------------------------------------------------------------------- |
| `noOpen`             | 啟動開發伺服器但不自動開啟瀏覽器。                                         |

| `logTab`        | `dev`、`start`、`preview` | 依分頁 ID 過濾記錄。                           |

### 編譯期常數

使用 `define` 把常數內嵌進每個 bundle。Extension.js 會把每個值序列化為 JSON，所以字串、數字、布林值與一般物件都可以：

```js
export default {
  define: {
    __APP_VERSION__: "1.4.0",
    __IS_FIREFOX__: false,
  },
  browser: {
    firefox: { define: { __IS_FIREFOX__: true } },
  },
};
```

你的程式碼把 `__APP_VERSION__` 當成一個裸識別字來讀取，建置會把它換成對應的值。在 TypeScript 專案裡，每個鍵還會在產生的 `extension-env.d.ts` 中得到一條環境宣告，所以 `__APP_VERSION__` 會以 `string` 通過型別檢查。

### 特殊資料夾的位置

使用 `folders` 移動某個[特殊資料夾](/zh-Hant/docs/features/special-folders)，或把它關掉。路徑從專案根目錄解析：

```js
export default {
  folders: {
    scripts: "src/scripts",
    public: "src/assets",
    pages: false,
  },
};
```

| 鍵        | 預設值     | 接受的值                                   |
| --------- | ---------- | ------------------------------------------ |
| `scripts` | `scripts/` | 指向名為 `scripts` 的資料夾的路徑，或 `false` |
| `pages`   | `pages/`   | 指向名為 `pages` 的資料夾的路徑，或 `false`   |
| `public`  | `public/`  | 指向任意資料夾的路徑，或 `false`           |

- 移動後的 `scripts` 或 `pages` 資料夾必須保留原名。Extension.js 不會讀取 `src/injected` 這樣的路徑。
- `false` 會關掉這個資料夾。Extension.js 不再把其中的檔案編譯成進入點，也不再複製 `public` 資料夾。
  - 被關掉的 `scripts` 資料夾裡、由你的程式碼點名的腳本（例如在 `chrome.scripting.executeScript({files})` 中）仍然會發佈。Extension.js 會像編譯其他資料夾裡的腳本一樣編譯它，不加內容腳本包裝。
  - 被關掉的 `public` 資料夾裡的任何內容都不會發佈，`/icon.png` 這樣的根路徑也不再指向那裡。如果 manifest 仍然點名那裡的檔案，建置會失敗並逐一列出這些檔案。如果頁面或樣式表參照了那裡的檔案，建置會為每處參照印出一則警告。請重新開啟這個資料夾，或把檔案移出 `public/`。
- 移動後的資料夾與預設資料夾的行為完全一致。移動後的 `scripts` 資料夾裡的腳本會得到內容腳本包裝，並在 `dev` 中原地重新載入。移動後的 `pages` 資料夾裡的頁面會建置到同樣的 `pages/` 輸出。頁面、樣式表或 manifest 用同樣的根路徑（例如 `/logo.png`）就能存取移動後的 `public` 資料夾裡的檔案。
- 當 `public` 指定了路徑時，Extension.js 只從那個資料夾複製。
- `browser.<vendor>.folders` 會整個取代頂層物件，`commands.<cmd>.folders` 則同時取代這兩者。兩者都不會逐鍵合併。

### Rspack 設定

需要進階的 bundler 客製化？使用 `config` 來修補產生出的 Rspack 設定：

```js
export default {
  config: (config) => {
    config.module.rules.push({
      test: /\.mdx$/,
      use: ["babel-loader", "@mdx-js/loader"],
    });
    return config;
  },
};
```

`config` 也可以是物件，Extension.js 會把它合併到產生出的設定之上。

`config` 在 Extension.js 掛上它的 loader 規則之前執行。要讀取或修改最終的設定，請使用 `configResolved`。它在每次 `dev`、`build` 或 `start` 執行中只跑一次，就在第一次編譯之前，並收到已掛上所有 loader 規則的 Rspack 設定：

```js
export default {
  configResolved: (config) => {
    config.module.rules.push({
      test: /\.graphql$/,
      type: "asset/source",
    });
    return config;
  },
};
```

這個 hook 可以修改 `module`、`resolve`、`resolveLoader`、`node`、`optimization.minimize`、`optimization.minimizer`，以及 Rspack 在建置開始時才讀取的 `output` 選項，例如檔案名稱與 `environment`。可以就地修改它們，也可以回傳一個新的設定物件。這個 hook 可以是非同步的，什麼都不回傳的 hook 會讓設定維持原樣。

到這時 Rspack 已經消耗了其餘所有鍵。這包括 `entry`、`plugins`、`context`、`mode`、`target`、`devtool`、`externals`、`experiments` 與 `performance` 這類鍵，`minimize` 與 `minimizer` 之外的所有 `optimization` 鍵，以及這些 `output` 鍵：`path`、`module`、`library`、`enabledLibraryTypes`、`chunkFormat`、`chunkLoading`、`enabledChunkLoadingTypes`、`wasmLoading`、`enabledWasmLoadingTypes`、`workerChunkLoading`、`workerWasmLoading`、`workerPublicPath`、`pathinfo`、`sourceMapFilename`、`devtoolModuleFilenameTemplate`、`devtoolFallbackModuleFilenameTemplate`、`devtoolNamespace`、`bundlerInfo`。對其中任何一個的修改，包括深入到值內部的修改，Extension.js 都會復原，並印出一則依路徑列出每個鍵的警告。請在 `config` 裡設定它們。

#### hook 上下文

兩個 hook 都會收到第二個引數，用來說明本次執行。它帶有 `browser`（目標瀏覽器，與 `--browser` 的寫法一致）、`mode`（`development`、`production` 或 `none`）和 `command`（`dev`、`build`、`start` 或 `preview`）。用它為某一個瀏覽器修改 bundler，而不必讀取 `process.argv`。下面的範例讓 Firefox 的商店建置保持可讀，方便審核：

```js
export default {
  config: (config, { browser, command }) => {
    if (browser === "firefox" && command === "build") {
      config.optimization.minimize = false;
    }
    return config;
  },
};
```

`extension` 套件為這個引數匯出了 `ConfigHookContext` 型別。只接收一個引數的 hook 仍然可以正常運作。

#### 為某一個瀏覽器保留一組 locale

商店接受的語言可能少於你的 `_locales` 資料夾所包含的語言。Extension.js 會為每個瀏覽器複製整個資料夾。要為某一個瀏覽器只發布其中一部分，請從 `config` 推入一個外掛，刪除其他 locale 的資源：

```js
const KEEP = { edge: ["en", "de"] };

export default {
  config: (config, { browser }) => {
    const keep = KEEP[browser];
    if (!keep) return config;
    config.plugins.push({
      apply(compiler) {
        compiler.hooks.thisCompilation.tap("keep-locales", (compilation) => {
          compilation.hooks.processAssets.tap(
            {
              name: "keep-locales",
              stage: compiler.rspack.Compilation.PROCESS_ASSETS_STAGE_OPTIMIZE,
            },
            () => {
              for (const name of Object.keys(compilation.assets)) {
                const match = /^_locales\/([^/]+)\//.exec(name);
                if (match && !keep.includes(match[1])) {
                  compilation.deleteAsset(name);
                }
              }
            },
          );
        });
      },
    });
    return config;
  },
};
```

有了這個檔案，`extension build --browser=edge` 只會發布 `_locales/en` 與 `_locales/de`。其他所有瀏覽器仍保留整個資料夾。過濾器必須保留 `default_locale` 所指的資料夾。當它刪除了那個資料夾時，建置會失敗，並在錯誤中指出該 locale。

## 完整範例

```js
export default {
  browser: {
    chrome: { browser: "chrome", profile: "default" },
    firefox: { browser: "firefox", persistProfile: true },
    "chromium-based": {
      browser: "chromium-based",
      chromiumBinary:
        "/Applications/Brave Browser.app/Contents/MacOS/Brave Browser",
    },
  },
  commands: {
    dev: {
      browser: "chrome",
      polyfill: true,
      host: "0.0.0.0",
      extensions: { dir: "./extensions" },
    },
    start: { browser: "edge" },
    preview: { browser: "firefox" },
    build: {
      zipFilename: "extension.zip",
      zip: true,
      zipSource: true,
    },
  },
  extensions: { dir: "./extensions" },
  transpilePackages: ["@workspace/ui"],
  config: (config) => config,
};
```

## 最佳實務

- **瀏覽器專屬值放在 `browser`**：讓指令定義專注於工作流程，而非瀏覽器內部細節。
- **有意識地使用頂層預設**：把共用的 `extensions` / `transpilePackages` 放在根層，只在需要的地方覆寫。
- **優先使用 `chromiumBinary`／`geckoBinary` 名稱**：它們與當前的指令與型別介面一致。
- **`config` hook 保持最小**：只補上 Extension.js 一級選項尚未涵蓋的部分。
