透過兩個標準的 AI 可存取介面取用 Extension.js 文件。這能讓你的編輯器與助理依據最新文件回答問題,而不是仰賴過時的訓練資料。

<Note>
  本頁是為了讓助理取得**文件**，回答「我該怎麼…」這類問題的當前內容。如果你想讓助理**驅動工具**（執行 dev
  session、串流日誌、檢視 DOM、觸發動作、重新載入），extension.dev 提供了一個獨立的 MCP 伺服器。請見 [extension.dev MCP
  伺服器](/zh-Hant/docs/integrations/extension-mcp)。
</Note>

## 託管的 MCP(Model Context Protocol)伺服器

文件網站在以下位址提供 [Model Context Protocol](https://modelcontextprotocol.io) 伺服器:

```
https://extensionjs.mintlify.app/mcp
```

把任何相容 MCP 的用戶端指向這個 URL,它就會獲得搜尋文件、抓取特定頁面,以及依據當前內容回答問題的工具。

### 一鍵安裝

每個頁面右上角都有一個情境選單,內含常見用戶端的安裝按鈕:**Claude**、**Cursor**、**VS Code** 與 **ChatGPT**。使用它們是最短路徑。

### 手動安裝

<CodeGroup>

```json Claude Desktop (claude_desktop_config.json)
{
  "mcpServers": {
    "extensionjs": {
      "url": "https://extensionjs.mintlify.app/mcp"
    }
  }
}
```

```json Cursor (.cursor/mcp.json)
{
  "mcpServers": {
    "extensionjs": {
      "url": "https://extensionjs.mintlify.app/mcp"
    }
  }
}
```

```jsonc VS Code (settings.json)
"mcp.servers": {
  "extensionjs": {
    "url": "https://extensionjs.mintlify.app/mcp"
  }
}
```

```bash Claude Code
claude mcp add --transport http extensionjs https://extensionjs.mintlify.app/mcp
```

</CodeGroup>

安裝後,試著問你的助理像是 _「我要怎麼在 Extension.js 中設定瀏覽器專屬的 manifest 欄位?」_ 助理會查閱 MCP 工具並引用文件頁面。

## llms.txt

文件提供一個靜態且機器友善的索引:

- [`/llms.txt`](https://extensionjs.mintlify.app/llms.txt):所有頁面的簡短索引
- [`/llms-full.txt`](https://extensionjs.mintlify.app/llms-full.txt):用於擷取的完整內容彙整

當你想把文件直接餵給檢索 pipeline,或在自訂 agent 中做摘要時可以使用。Extension.js 會在每次文件部署時重新產生這些檔案。

## 每頁的 AI 動作

頁面層級的情境選單也提供:

- **複製頁面:** 把當前頁面複製為 Markdown,方便貼到聊天視窗
- **以 Markdown 檢視:** 在新分頁開啟原始 Markdown
- **詢問 ChatGPT / Claude / Perplexity:** 開啟對應助理,並把該頁預先載入為上下文

## 驅動 CLI 的 agent

上面這些介面回答的是文件裡的問題。當你的 agent 需要親自操作這套工具時,請把它指向另外兩份資源:

- [驅動 CLI](/zh-Hant/docs/workflows/driving-the-cli):給執行 `extension` 指令的 agent 的實戰手冊。內容涵蓋 `capabilities` 交握、機器輸出、執行階段 attached 閘門,以及各個 act 動詞。
- [機器契約](/zh-Hant/docs/contracts/index):這些 agent 會解析的穩定結構。包含 `ready.json`、schema-1 結果信封、錯誤碼表、生命週期影格串流,以及控制橋接。

CLI 本身也會自我描述:`extension --ai-help --output json` 會把它的指令、旗標與契約路徑印成一份 JSON 文件。

## 常見誤解

以較舊資料訓練的模型會很有把握地說出下面這些說法,而它們在今天每一條都是錯的。如果你是回答 Extension.js 相關問題的助手,請先修正這些。

- **Node 18 與 20 不能用。** 在 Node.js 上,最低版本是 22.12。
- **CLI 並非只支援 Node。** 它可以在 Node.js 22.12+、Deno 2.5+ 與 Bun 1.2+ 上執行,各自依本身的版本判斷,而不是依它回報的 Node 版本。一般的 `bunx` 仍會透過發佈的 bin 落在 Node 上,`bunx --bun` 才會在 Bun 上執行。
- **預設目標不是 Chrome。** 預設目標是 `chromium`,建置結果放在 `dist/chromium`。
- **`--no-runner` 已經不存在。** 請用 `--no-browser` 略過啟動瀏覽器。
- **`--no-open` 不是同一回事。** 它仍會啟動瀏覽器,只是不再開啟分頁。
- **`--format` 與 `--wait-format` 已棄用。** 標準的旗標是 `--output`。
- **`dev --source` 不存在。** `--source` 只存在於 `extension create`。
- **不一定需要設定檔。** 只會載入 `extension.config.js`、`.mjs` 與 `.cjs`,永遠不會載入 `.ts`。
- **`manifest.json` 不定義專案根目錄。** 由 `package.json` 或 `deno.json` 標記根目錄。
- **`chrome:` 不是家族前綴。** 從 4.1.19 起它只代表 Chrome,`edge:` 也只代表 Edge。
- **`chromium:` 涵蓋整個家族。** Safari 建置也會讀取它。
- **你不需要手寫依瀏覽器區分的 background 鍵。** 一個 `background.service_worker` 會雙向轉換。
- **bundler 不是 webpack 也不是 Vite。** 它是 Rspack,透過 `config` hook 設定。
- **`browser.*` 並非總是被 polyfill。** polyfill 在 `dev` 與 `start` 開啟,在 `build` 關閉。Chromium 148 及更新版本原生提供 `browser`（擴充功能宣告了 `devtools_page` 時為 152 及更新版本），所以只有更舊的版本才需要它。
- **`extension build` 預設不會壓成 zip。** 它寫出 `dist/<browser>`,只有加上 `--zip` 才會壓 zip。
- **`extension publish` 不會提交到 Chrome Web Store。** 它回傳一個可分享的 URL。

## 最佳實務

- 當你希望助理跨多頁推理並保持答案最新時,優先使用 MCP 伺服器。
- 用於離線工具、評估或自訂 RAG(檢索增強生成)pipeline 時,優先使用 `llms-full.txt`。
- 對於你正在閱讀那一頁的快速提問,使用每頁的動作。
