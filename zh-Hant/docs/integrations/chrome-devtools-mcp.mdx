[chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp) 讓 AI agent 直接控制一個執行中的 Chrome 實例。近期版本加入了擴充功能工具：`install`、`list`、`reload`、`trigger` 和 `uninstall`，以及 service worker 日誌。它是 Google 的專案，並不了解你的建置。它可以很好地搭配 Extension.js dev session 使用，後者負責建置、重新載入和產生的 manifest。

## 它為 dev session 帶來什麼

- 驅動任意頁面：點擊、捲動、填寫表單。
- 效能追蹤、Lighthouse 稽核和網路檢視。
- 檢視不是你建置的擴充功能。
- 用真實使用者手勢觸發工具列 action。

所有涉及你專案的操作仍由 Extension.js 負責：`extension dev` 負責建置和重新載入，`extension logs`、`extension eval`、`extension storage` 和 `extension open` 負責觀察和控制。請見[除錯](/zh-Hant/docs/debugging)。

## 手勢注意事項

`extension open action` 會在沒有使用者手勢的情況下重播你的 `chrome.action.onClicked` 處理函式。它可腳本化、可無頭執行，並且在 Chromium 和 Firefox 上都能運作，但它不會授予 `activeTab`。當處理函式依賴該授權時，請使用 chrome-devtools-mcp 的 `trigger_extension_action`，它透過 Puppeteer 點擊真實按鈕。它僅支援 Chromium，並且需要可見視窗。重播機制請見[觸發 action 與鍵盤命令](/zh-Hant/docs/debugging/trigger-actions-and-commands)。

<Note>
  chrome-devtools-mcp 的擴充功能工具（`--categoryExtensions`）需要管線連線。在 Chrome 149 之前，該類別不支援透過 WebSocket 端點附加到已在執行的瀏覽器。
</Note>

## 與 extension.dev MCP 伺服器並用

extension.dev 提供一個 MCP 伺服器，把同一個 session 以工具的形式提供給 agent。這些工具以 `extension_*` 為命名空間，因此兩個伺服器不會衝突。雙伺服器設定、能力對照表和「該用哪個」表格請見 [docs.extension.dev/tools/chrome-devtools-mcp](https://docs.extension.dev/tools/chrome-devtools-mcp)。
