跨擴充功能各介面維持樣式表品質的一致性，並及早攔截 CSS 問題。Stylelint 會透過 scripts 或持續整合（CI）執行，而不是透過 Extension.js 的 dev/build pipeline。

## 什麼情況下適合使用 Stylelint

- 你在多個擴充功能介面之間維護共用的 CSS/Sass/Less。
- 你希望在 pull request 合併前進行樣式品質檢查。
- 你需要在團隊流程中維持一致的樣式表慣例。

## Stylelint 能做到的事

| 能力               | 帶來什麼好處                         |
| ------------------ | ------------------------------------ |
| CSS 品質檢查       | 抓出不合法的寫法並強制套用樣式慣例   |
| 預處理器支援       | 在同一流程中檢查 CSS、Sass 與 Less   |
| 與 Script、CI 整合 | 在合併與發佈前執行樣式檢查           |
| 與格式化工具對齊   | 與 Prettier 搭配以減少樣式工具的衝突 |

## 範本範例

### Stylelint 設定範本

預先設定好的樣式檢查範本。

![`new-config-stylelint` screenshot](/images/examples/newtab-config-stylelint/screenshot.png)

<CodeGroup>

```bash npm
npx extension@latest create my-extension --template=newtab-config-stylelint
```

```bash pnpm
pnpx extension@latest create my-extension --template=newtab-config-stylelint
```

```bash yarn
yarn dlx extension@latest create my-extension --template=newtab-config-stylelint
```

```bash bun
bunx extension@latest create my-extension --template=newtab-config-stylelint
```

```bash deno
deno run -A npm:extension@latest create my-extension --template=newtab-config-stylelint
```

</CodeGroup>

Repository: [examples/newtab-config-stylelint](https://github.com/extension-js/examples/tree/main/examples/newtab-config-stylelint)

## 在既有擴充功能中使用

安裝 Stylelint 相依套件：

<CodeGroup>

```bash npm
npm install -D stylelint stylelint-config-standard-scss
```

```bash pnpm
pnpm add -D stylelint stylelint-config-standard-scss
```

```bash yarn
yarn add -D stylelint stylelint-config-standard-scss
```

```bash bun
bun add -d stylelint stylelint-config-standard-scss
```

```bash deno
deno add -D npm:stylelint npm:stylelint-config-standard-scss
```

</CodeGroup>

### Stylelint 設定

在專案根目錄建立 Stylelint 設定檔（例如 `.stylelintrc.json`）：

```json
{
  "extends": "stylelint-config-standard-scss",
  "rules": {
    "color-no-invalid-hex": true,
    "block-no-empty": true
  }
}
```

### 執行 Stylelint

<CodeGroup>

```bash npm
npm run lint:styles
```

```bash pnpm
pnpm lint:styles
```

```bash yarn
yarn lint:styles
```

```bash bun
bun run lint:styles
```

```bash deno
deno task lint:styles
```

</CodeGroup>

如果尚未建立對應的 script：

<CodeGroup>

```bash npm
npx stylelint '**/*.{css,scss,sass,less}'
```

```bash pnpm
pnpm exec stylelint '**/*.{css,scss,sass,less}'
```

```bash yarn
yarn stylelint '**/*.{css,scss,sass,less}'
```

```bash bun
bunx stylelint '**/*.{css,scss,sass,less}'
```

```bash deno
deno run -A npm:stylelint '**/*.{css,scss,sass,less}'
```

</CodeGroup>

## 與 Prettier 整合

將 Stylelint 與 Prettier 整合，一起格式化與檢查樣式。安裝下列相依套件：

<CodeGroup>

```bash npm
npm install -D stylelint-prettier prettier
```

```bash pnpm
pnpm add -D stylelint-prettier prettier
```

```bash yarn
yarn add -D stylelint-prettier prettier
```

```bash bun
bun add -d stylelint-prettier prettier
```

```bash deno
deno add -D npm:stylelint-prettier npm:prettier
```

</CodeGroup>

接著更新 `.stylelintrc.json` 以納入 Prettier：

```json
{
  "extends": [
    "stylelint-config-standard-scss",
    "stylelint-prettier/recommended"
  ]
}
```

這樣可讓樣式格式化與檢查維持一致。

## 最佳實務

- 維持一個專屬的 `lint:styles` 指令，並在 CI 中執行。
- 在 monorepo 中跨擴充功能套件共用同一份設定。
- 將 Stylelint 與 Prettier 搭配使用，讓樣式格式化結果可預期。

## 偵測機制

Extension.js 不會讀取 Stylelint 設定，也不會把 Stylelint 注入建置 pipeline。請透過你自己的指令碼執行 Stylelint。
