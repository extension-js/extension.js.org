只要你的專案使用啟用 Tailwind 的 React 環境，shadcn/ui 在擴充功能裡就和在 web app 中一樣可用。元件存放在你的原始碼樹（不是 `node_modules`）裡，因此你可以完整掌控樣式與行為。

## 什麼情況下適合使用 shadcn/ui

- 你需要在 sidebar、popup 與 options 介面之間共用 UI 原語。
- 你在產品端的程式碼已經使用 React + Tailwind。
- 你希望採用「以原始碼為主」的元件，讓團隊可以完全自訂。

## shadcn/ui 能做到的事

| 能力                    | 帶來什麼好處                                      |
| ----------------------- | ------------------------------------------------- |
| 以原始碼為主的 UI 元件  | 將產生的 `components/ui/*` 檔案納入專案版本控制   |
| React + Tailwind 一致性 | 採用與現代 web app 技術棧相同的撰寫方式           |
| 跨擴充功能介面重複使用  | 在 sidebar、popup 與 options 頁面之間共用元件原語 |
| 漸進式採用              | 從範本起步，再隨時間擴大元件覆蓋範圍              |

## 技術棧假設

- React + TypeScript
- Tailwind CSS
- PostCSS（`@tailwindcss/postcss`）
- 本機的 `components/ui/*` 元件檔（shadcn 風格的結構）

## 在既有專案中手動設定

1. 設定 Tailwind 與 PostCSS（請參考 [Tailwind CSS](/zh-Hant/docs/integrations/tailwindcss)）。
2. 在專案中初始化 shadcn，並產生元件。
3. 將產生的 UI 元件放在擴充功能原始碼中（例如 `src/components/ui/`）。
4. 在 UI 渲染的擴充功能入口檔匯入你的 Tailwind 樣式表。

### PostCSS 範例（Tailwind v4）

```js
export default {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};
```

### `components.json` 範例

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "tsx": true,
  "tailwind": {
    "css": "sidebar/styles.css",
    "cssVariables": true
  }
}
```

## 使用方式

從本機 import 使用產生的元件：

```tsx
import { Button } from "@/components/ui/button";
import "./styles.css";

export default function MyComponent() {
  return <Button className="text-lg font-semibold">Click Me</Button>;
}
```

## Content script 注意事項

- 擴充功能頁面（popup、options、sidebar、new tab）是 shadcn/ui 最容易上手的場景。
- 在 content script 裡，單純的 `import "./styles.css"` 求值得到的是這份樣式表的 URL。它本身不會替任何東西加上樣式。
- Extension.js 只在一種情況下替你放置這份樣式表。這條匯入必須寫在已宣告 content script 的入口檔裡，而且腳本必須用 `data-extension-root` 標記一個宿主元素。
- 樣式表隨後進入這個宿主的 shadow root。把元件掛載到這個 shadow root 裡，Tailwind 樣式表才能作用到它們。

從 4.1.39 之後的版本起，如果 content script 匯入了一份沒有任何程式碼放置的樣式表，建置會印出警告：

```text
A stylesheet imported only for its side effect styles nothing in a content script.
PATH content/scripts.tsx:1
IMPORT import './styles.css'
There the import evaluates to the sheet as a data: URL, and no code reads it.
Read the value and place it: import href from './styles.css', then set it on a <link rel="stylesheet">.
Or list the sheet under content_scripts[].css in manifest.json, or use a CSS module (.module.css).
Extension.js places it for you only in the shadow root of a host marked data-extension-root.
```

最後兩行只會在 manifest 宣告的 content script 上印出。所有可用的方式見 [content script 中的樣式](/zh-Hant/docs/implementation-guide/css#content-script-中的樣式)，宿主元素見 [Shadow DOM](/zh-Hant/docs/implementation-guide/shadow-dom)。

## 最佳實務

- 把 shadcn/ui 當作以原始碼為主的元件，而不是執行期匯入的 UI 套件。
- 讓 Tailwind 的 config/content 路徑與你的擴充功能資料夾（`pages`、`scripts`、`src`）對齊。
- 先從單一介面（例如 sidebar 或 popup）開始，再處理 content script 的渲染複雜度。
- 將共用 token 與 utility helper 放在專屬檔案中（`lib/utils`、設計 token、主題變數）。
