只有在你需要 SWC（Speedy Web Compiler）無法涵蓋的轉換或外掛時，才加入 Babel。將 SWC 維持為預設的 pipeline，然後把 Babel 限縮在真正需要它的檔案。

## 什麼情況下適合使用 Babel

- 你依賴只在 Babel 上才有的外掛或 preset。
- 你正在逐步遷移一個重度使用 Babel 的既有專案。
- 你想針對特定檔案類型（例如 MDX）套用具針對性的轉換。

## Babel 能做到的事

| 能力                                   | 帶來什麼好處                                                          |
| -------------------------------------- | --------------------------------------------------------------------- |
| 針對性轉換                             | 只針對特定檔案類型（例如 MDX）執行 Babel，而不需替換整條建置 pipeline |
| 接通 Babel 外掛生態                    | 使用既有 web 專案中只在 Babel 上的 preset/plugin                      |
| 漸進式遷移                             | 以更小的步驟把舊有的 Babel 擴充功能專案遷移到 Extension.js            |
| 與 Rspack（Extension.js 打包工具）整合 | 透過 `extension.config.*` 的 `config` hook 設定 Babel                 |

## 範例設定

安裝 Babel 相依套件：

<CodeGroup>

```bash npm
npm install -D @babel/core @babel/preset-env babel-loader
```

```bash pnpm
pnpm add -D @babel/core @babel/preset-env babel-loader
```

```bash yarn
yarn add -D @babel/core @babel/preset-env babel-loader
```

```bash bun
bun add -d @babel/core @babel/preset-env babel-loader
```

```bash deno
deno add -D npm:@babel/core npm:@babel/preset-env npm:babel-loader
```

</CodeGroup>

建立 `babel.config.json`：

```json
{
  "presets": ["@babel/preset-env"]
}
```

在 `extension.config.js` 中只把 Babel 串接到 MDX：

```js
export default {
  config: (config) => {
    config.module.rules.push({
      test: /\.mdx$/,
      use: ["babel-loader", "@mdx-js/loader"],
    });
    return config;
  },
};
```

## 你的 Babel 設定在 SWC 之前執行

從 4.2.0 之後的版本起，專案資料夾裡的 Babel 設定不需要你加任何規則就會執行。Extension.js 會尋找 `babel.config.*`、`.babelrc`、`.babelrc.*` 或 `package.json` 裡的 `babel` 鍵，並讓 Babel 先處理每一個專案指令稿，但從不處理 `node_modules`。接著 SWC 編譯 Babel 的輸出，所以 TypeScript、JSX、瀏覽器目標與 React Refresh 仍由 SWC 負責。你的設定不需要 TypeScript 或 JSX 預設集，因為 Extension.js 會給 Babel 讀取這些檔案所需的語法外掛。Extension.js 為此內建 `babel-loader` 與 `@babel/core`。沒有 Babel 設定的專案永遠不會為指令稿載入 Babel。

```json babel.config.json
{
  "plugins": ["babel-plugin-macros"]
}
```

所以前面設定步驟裡的 `babel.config.json` 也會作用於專案裡的每一個指令稿。4.2.0 及之前的版本只透過你加入的規則執行 Babel。

Babel 無法取代 SWC。`config` 裡的規則只能加入 loader，不能移除 loader，所以 SWC 仍會在 Babel 之後編譯你的指令稿。請見 [Loader 順序](/zh-Hant/docs/features/extension-configuration#loader-順序)。

## 最佳實務

- Babel 設定只放 SWC 缺少的外掛，因為它會作用於每一個專案指令稿。
- 明確列出 Babel 規則，讓 loader 順序維持可預期。
- 只在遷移或外掛相容性必要的地方重複使用 Babel。
