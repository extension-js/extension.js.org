Extension.js 用 SWC 編譯 TypeScript，它只抹除型別，從不檢查型別。型別檢查是你用 `tsc` 另外執行的一步。本頁說明這一步如何解析 `chrome.*`、`browser.*` 與 `process.env`。

## Extension.js 會產生什麼

當專案使用 TypeScript 時，`extension dev`、`extension build` 與 `extension start` 會在 `package.json` 旁邊寫下一個 `extension-env.d.ts` 檔案。它在每次執行時都會重新產生，所以不要編輯它。

這個檔案會引入 `extension` 套件所發佈的環境型別：

```ts extension-env.d.ts
/// <reference types="extension/types" />
/// <reference types="extension/types/polyfill" />
```

這些引用會給你：

| 引用                       | 它宣告了什麼                                                          |
| -------------------------- | --------------------------------------------------------------------- |
| `extension/types`          | `browser` namespace 及其別名 `chrome`、`process.env` 與 `import.meta.env` 鍵 |
| `extension/types/polyfill` | `webextension-polyfill` 模組，供 `import browser from 'webextension-polyfill'` 使用 |
| 萬用字元模組               | 對 `.css`、`.module.css`、`.png`、`.svg` 等資源的 `import`，以及 `?raw` 與 `?url` 匯入 |

`EXTENSION_*` 環境變數鍵也在這裡取得型別。這就是 `process.env.EXTENSION_MODE` 不需要額外設定就能解析的原因。

安裝了 `@types/chrome` 的專案，第一條引用會不一樣。本頁的「保留 @types/chrome」一節展示了它。

當 `extension` 套件無法從專案裡解析時（例如只透過 `npx` 執行 CLI 的專案），這兩條引用什麼也找不到。這時產生的檔案還會把萬用字元模組宣告直接寫在檔案裡，所以樣式表、圖片、`?raw` 與 `?url` 匯入仍然能通過型別檢查。

## 隨 Extension.js 一起安裝的型別

`extension` 套件把這些引用需要的三個型別套件列為相依套件：

| 套件                           | 它提供的型別             |
| ------------------------------ | ------------------------ |
| `chrome-types`                 | `browser.*` namespace 及其別名 `chrome.*` |
| `@types/webextension-polyfill` | `webextension-polyfill` 模組 |
| `@types/node`                  | `process.env`            |

[`chrome-types`](https://www.npmjs.com/package/chrome-types) 是 Chrome 從 Chromium 原始碼產生的套件。它的 `browser` 是原生 namespace，方法回傳 Promise。`chrome` 是它的別名。

`chrome-types` 沒有宣告只有 Firefox 才有的 API。Firefox 的 `browser.sidebarAction` 與 `browser.browserAction` 由 Extension.js 自己提供型別。

它們會隨 `extension` 一起安裝，所以在一個新專案裡，`tsc` 不需要額外安裝就能解析 `chrome.*` 與 `browser.*`：

```bash
npx tsc --noEmit
```

建置並不需要這些套件。SWC 從來不讀型別，所以不論有沒有它們，建置都會成功。

## 保留 @types/chrome

安裝了 `@types/chrome` 的專案會繼續使用它。`chrome` 的型別來自這個套件，`browser` 的型別和以前一樣來自 `webextension-polyfill`。

`@types/chrome` 與 `chrome-types` 都宣告了 `chrome` 全域變數，所以這兩個套件不能同時載入。產生的 `extension-env.d.ts` 只引用其中一個。當你的 `package.json` 列出了 `@types/chrome` 時，它引用 `@types/chrome`。當專案資料夾或某個上層資料夾裡存在 `node_modules/@types/chrome` 時，也是如此：

```ts extension-env.d.ts
/// <reference types="extension/types/legacy" />

// This project installs @types/chrome, so it types the extension APIs.
// Remove that package to get chrome-types and the native browser namespace.
/// <reference types="chrome" />

// Polyfill types for browser.* APIs
/// <reference types="extension/types/polyfill" />
```

改用 `chrome-types`：

1. 從專案裡移除 `@types/chrome`。
2. 執行一次 `extension dev` 或 `extension build`。

回到 `@types/chrome`：

1. 把 `@types/chrome` 安裝為開發相依套件。
2. 執行一次 `extension dev` 或 `extension build`。

在預設設定下，`browser` 全域變數擁有原生型別。想要 `webextension-polyfill` 的型別，請匯入這個模組：

```ts
import browser from "webextension-polyfill";
```

## 固定你自己的版本

`extension` 套件接受 `@types/node` 與 `@types/webextension-polyfill` 的任何版本。它接受 `chrome-types` 0.1.460 或更高版本。當你的專案自己宣告了其中一個時，npm、pnpm 與 Bun 會重複使用你的專案所安裝的那一份。

當你的 `tsconfig.json` 沒有 `types` 陣列時，TypeScript 也會載入你的專案所宣告的那一份。以你自己 `package.json` 裡的版本為準：

```json package.json
{
  "devDependencies": {
    "@types/webextension-polyfill": "^0.12.0"
  }
}
```

## 使用 Extension.js 4.1.18 或更早版本的專案

在 4.1.19 之前，`extension/types` 引用了 `chrome`，但不會安裝 `@types/chrome`。一個呼叫 `chrome.*`、卻沒有自己那一份型別的專案跑 `tsc` 會失敗：

```plaintext
src/background.ts(19,1): error TS2304: Cannot find name 'chrome'.
src/content/scripts.ts(87,30): error TS2503: Cannot find namespace 'chrome'.
```

把 `extension` 升級到 4.1.19 或更新的版本。如果你留在更早的版本上，請手動安裝這個套件：

<CodeGroup>

```bash npm
npm install -D @types/chrome
```

```bash pnpm
pnpm add -D @types/chrome
```

```bash yarn
yarn add -D @types/chrome
```

```bash bun
bun add -d @types/chrome
```

```bash deno
deno add -D npm:@types/chrome
```

</CodeGroup>

在這些版本上，裝上 `@types/webextension-polyfill` 之前，`browser` 的型別是 `any`。想為 `browser.*` 提供型別，請把這個套件也裝上：

<CodeGroup>

```bash npm
npm install -D @types/webextension-polyfill
```

```bash pnpm
pnpm add -D @types/webextension-polyfill
```

```bash yarn
yarn add -D @types/webextension-polyfill
```

```bash bun
bun add -d @types/webextension-polyfill
```

```bash deno
deno add -D npm:@types/webextension-polyfill
```

</CodeGroup>

## 升級後出現型別錯誤

更早的版本會隨 `extension` 一起安裝 `@types/chrome`，並用 `webextension-polyfill` 為 `browser` 提供型別。安裝了 `@types/chrome` 的專案會保留這些型別。沒有 `@types/chrome` 的專案在升級後會改用 `chrome-types`。

改用之後，以前能通過 `tsc` 的程式碼可能會出現新的型別錯誤。例如，`tsc` 可能會回報 `chrome.tabs.TabChangeInfo` 這樣的名稱不存在。

安裝 `@types/chrome` 可以保留以前的型別，然後執行一次 `extension dev` 或 `extension build`。`browser.*` 在執行階段那一側的樣子，請閱讀[跨瀏覽器相容](/zh-Hant/docs/features/cross-browser-compatibility)。

## 讓 extension-env.d.ts 留在 include 清單裡

只有當 TypeScript 讀得到它時，這個產生出來的檔案才有用。範本產生的 `tsconfig.json` 會點名它：

```json tsconfig.json
{
  "include": ["./", "extension-env.d.ts"],
  "exclude": ["node_modules", "dist"]
}
```

當 Extension.js 為一個還沒有 `tsconfig.json` 的專案寫出一份 `tsconfig.json` 時，那份檔案不帶 `include` 陣列。TypeScript 於是會讀取專案資料夾底下的每一個檔案，所以照樣找得到 `extension-env.d.ts`。而一個你自己寫、卻漏掉這個檔案的 `include` 陣列，會讓資源匯入與 `browser` 全域變數一起失效。

從 4.1.39 之後的版本起，只有當你的 `tsconfig.json` 會在 `package.json` 旁邊讀到這個檔案時，Extension.js 才會建立它。沒有 `include` 陣列、`include` 涵蓋了專案根目錄，或是 `include` 或 `files` 點名了這個檔案，都屬於這種情況。如果 `include` 比較窄，例如 `["src"]`，這個檔案就不會被建立，所以請把它加進去：

```json tsconfig.json
{
  "include": ["src", "extension-env.d.ts"]
}
```

已經存在的那一份無論如何都會保持最新。重新格式化它，例如換一種引號或去掉分號，不會觸發重寫。

## 症狀與修正

| 症狀                                | 原因                                                 | 修正                                              |
| ----------------------------------- | ---------------------------------------------------- | ------------------------------------------------- |
| `Cannot find name 'chrome'`         | Extension.js 4.1.18 或更早，而且沒有 `@types/chrome` | 升級到 4.1.19，或安裝 `@types/chrome`             |
| `Cannot find namespace 'chrome'`    | 同樣的原因，只是出現在型別位置                       | 升級到 4.1.19，或安裝 `@types/chrome`             |
| `Cannot find module './styles.css'` | `extension-env.d.ts` 落在 `include` 之外             | 把這個檔案加進 `include`                          |
| `Cannot find name 'browser'`        | 專案從來沒跑過 `dev` 或 `build`                      | 跑一次任一指令來產生型別                          |
| 升級後 `chrome.tabs.TabChangeInfo` 這樣的名稱不存在 | 專案從 `@types/chrome` 改用了 `chrome-types` | 安裝 `@types/chrome`，然後跑一次 `dev` 或 `build` |
| CI 中已提交的 `extension-env.d.ts` 出現型別錯誤 | `tsc` 在 CLI 重寫這個檔案之前就執行了 | 在 `tsc` 之前執行 `dev`、`build` 或 `start` |

## 最佳實務

- 把 `extension-env.d.ts` 當成建置產物看待。你想提交它也可以，但絕不要編輯它。
- 只有當你需要某個型別套件的特定版本，或者想保留 `@types/chrome` 時，才在你自己的 `devDependencies` 裡宣告它。
- 在持續整合中執行 `tsc --noEmit`。Extension.js 的建置不會因為型別錯誤而失敗。
- 在持續整合中，先執行 `extension build`，再執行 `tsc`。`dev`、`build` 與 `start` 會重新產生 `extension-env.d.ts`，而 `tsc` 不會。
