知道哪些变更会即时生效、哪些需要重启，才能保持迭代速度。Extension.js 会为每次文件变更选择最轻量、最安全的更新模式。

## 更新模式

| 模式               | 发生了什么                           | 典型影响                            |
| ------------------ | ------------------------------------ | ----------------------------------- |
| 热模块替换 (HMR)   | 模块/样式更新就地生效                | 迭代最快，无需完整重启扩展          |
| `Hard reload`      | 目标浏览器会重载扩展运行时           | 扩展上下文重启，但 dev 进程继续运行 |
| 编译器重启         | 会话自行重建编译器并重载扩展         | 无需你操作即可应用入口与列表的变化  |
| `Restart required` | 一条警告要求你重启 `extension dev`   | 只有编辑 `extension.config.*` 时需要 |

## 常见示例

| 变更                                         | 期望行为                           |
| -------------------------------------------- | ---------------------------------- |
| 编辑 content script/组件代码                 | HMR/重新挂载路径(在受支持的场景下) |
| 编辑被 content scripts/页面使用的样式 import | HMR 风格的更新路径(视上下文而定)   |
| 编辑 `manifest.json` 中的非结构性值          | 硬重载流程                         |
| 增加/移除 manifest 入口引用                  | 会话自行重启                       |
| 修改 HTML 入口中的脚本/样式条目              | 会话自行重启                       |
| 增加 `pages/` 或 `scripts/` 入口             | 会话自行重启                       |
| 删除或重命名 `pages/` 或 `scripts/` 入口     | 会话自行重启（从 4.1.41 之后的版本开始） |
| 编辑 `extension.config.*`                    | 需要重启                           |
| 编辑 `_locales/*/messages.json`              | 硬重载流程                         |

## 何时需要重启

只有一种变更仍然需要你来重启：编辑 `extension.config.*`。会话会继续使用启动时读到的配置，并打印一条警告。请停止会话，重新运行 `extension dev`。

对于 manifest 入口的变化、HTML 入口中脚本或样式条目的变化、`.env` 的变化，以及在 `pages/` 或 `scripts/` 下添加文件，dev 会话都会自行重启编译器。从 4.1.41 之后的版本开始，在那里删除或重命名文件时也会这样做。

## 实用建议

- 在活跃的开发会话中，优先编辑现有模块/资产以获得最快反馈。
- 把结构性的 manifest 变更(入口列表编辑) 集中处理，这样会话只重启一次。
- 把"需要重启"的诊断当作权威：不重启而继续，可能会让你的运行时停留在过期状态。
