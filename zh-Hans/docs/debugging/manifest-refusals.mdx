有些 manifest 形态会让 Chromium 拒绝加载整个扩展。这种拒绝要么表现为一个原生对话框，要么根本什么都不显示，但绝不会是一条控制台报错。没有外力帮忙时，开发会话就这么卡住了：浏览器在跑，扩展却不在，调试通道也永远连不上。

Extension.js 在两个位置补上了这个缺口：

- **启动之前**，它会读取每一个即将加载的扩展的构建产物 `manifest.json`，并找出每一个能够确证的拒绝原因，点名具体字段和原因。到 4.1.41 为止，它会在浏览器启动之前发出警告。从 4.1.41 之后的版本开始，它会按住这个预测，等浏览器给出答复，每一次拒绝只打印一个区块，其中带着浏览器自己的那句话。
- **构建时**，它会修复一小组毫无歧义的致命形态，并为每一次修复打印一行修复说明。

## 被拒绝的加载会打印什么

从 4.1.41 之后的版本开始，Extension.js 会先按住自己的预测，等浏览器给出答复。浏览器拒绝扩展时，只打印一个区块，其中带着浏览器自己的那句话：

```plaintext
Chrome refuses to load this extension, so nothing in it runs.
PATH /path/to/project/dist/chrome
REASON Cannot install extension because it uses an unsupported manifest version.
Fix what the browser names, then run the command again.
```

- `REASON` 是浏览器的原话，写成一行。
- 当 manifest 能看出原因、而浏览器的原话没有说明时，后面会跟一行 `CAUSE`。见 [Firefox 的拒绝](#firefox-的拒绝)。
- 只有在无法询问浏览器时，才会打印预测。
- 如果浏览器加载了被预测会遭拒绝的形态，会有一条警告说明浏览器加载了它，并点名这个形态。

接下来发生什么取决于命令：

- **`start` 与 `preview`**：命令会停止浏览器，并以退出码 `1` 退出。
- **`dev`**：会话继续运行，并在下一次保存时重新尝试加载。

每一个界面都用代码 `E_EXTENSION_LOAD_REFUSED` 回答被拒绝的加载：

- `start`、`preview`、`dev --wait`、`start --wait` 以及 act 命令（`eval`、`storage` 等）回答状态 `load-refused`，并以退出码 `1` 退出。
- `dev --output json` 的流带有同样的状态和代码。
- `doctor --output json` 保持状态 `unhealthy`，并带上这个代码。

因拒绝而结束的已停止会话仍然会指出这次拒绝。`doctor` 和 act 命令会用这次拒绝和同样的代码回答。

## 启动前诊断

这些检查针对构建后的扩展运行，就在浏览器启动之前。从 4.1.41 之后的版本开始，每一条发现都会等待浏览器的答复。见[被拒绝的加载会打印什么](#被拒绝的加载会打印什么)。

### manifest 版本相关的拒绝

| 形态                                             | Chromium 为什么拒绝                                                    |
| ------------------------------------------------ | ---------------------------------------------------------------------- |
| 缺少 `manifest_version` | Chromium 拒绝整个扩展。 |
| 字符串（例如 `"3"`）、小数、`1` 或 `0` | Chromium 拒绝整个扩展。只有整数 2 或 3 才是 manifest 版本。 |
| `manifest_version: 2` 且没有 `theme` 键 | Chromium 拒绝整个扩展。Chrome 138 是最后一个支持 MV2 的版本。请改在 Firefox 上运行，或迁移到 MV3。 |

大于 3 的 `manifest_version` 不在这张表里，因为 Chromium 会加载它。见 [Chromium 会加载的形态](#chromium-会加载的形态)。

各浏览器对 Manifest V2 的支持并不相同：

- **Chrome**：Chrome 138 是最后一个支持 Manifest V2 的版本，Google 的 [Manifest V2 支持时间表](https://developer.chrome.com/docs/extensions/develop/migrate/mv2-deprecation-timeline)写明了这一点。
- **Chromium**：Chromium 151 移除了最后一个能以未打包方式加载 Manifest V2 扩展的标志。
- **Microsoft Edge**：Edge 已经弃用 Manifest V2，但仍然会运行它。在 2026-11-15 的实测中，Edge 157 加载并运行了一个未打包的 Manifest V2 扩展，没有任何警告。[Microsoft 的时间表](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/manifest-v3)没有给出最终版本。
- **Firefox 和 Safari**：两者都继续支持 Manifest V2。

Manifest V2 主题（带有 `theme` 键的 manifest）不会被标记。Chrome 151 仍然会安装它。

为 Chromium 目标构建 Manifest V2 扩展时，构建会打印一条警告，其中包含这些版本和几条出路：

```plaintext
This extension declares Manifest V2, and Chrome no longer runs it.
Chrome 138 was the last version to support Manifest V2, and Chrome 151 removed the flag that still loaded one unpacked.
The chrome build will not install. Options:

  • Build for Firefox (still supports MV2):  extension build --browser firefox
  • Migrate the manifest to MV3 (action, background.service_worker, host_permissions)
  • Or ship both from one source with browser-prefixed keys
    (chromium:manifest_version: 3, firefox:manifest_version: 2, …)
```

Edge 的构建打印的是一条弃用提示，附带同样的选项，因为 Edge 仍然会运行 Manifest V2。Edge 会话会正常启动扩展，不会把这个 manifest 算作拒绝：

```plaintext
This extension declares Manifest V2, which Microsoft Edge has deprecated.
Edge 157 still loads and runs one unpacked with no warning, and Microsoft names no final version yet.
Chrome 138 was the last Chrome version to support it. Options:
```

#### 每个会话只说一次

面向 Chromium 目标的 Manifest V2 项目，每个会话只会听到一次这个结论：

- **`dev` 和 `start`**：由上面的构建警告说出。启动之前不会再打印第二行。
- **`preview`**：不会运行构建，所以在启动之前用一行说出。

```plaintext
This extension declares Manifest V2, and Chrome no longer runs it.
PATH /path/to/project/dist/chrome
Chrome 138 was the last version to support Manifest V2, and Chrome 151 removed the flag that still loaded one unpacked.
Run it on a browser that keeps Manifest V2 (--browser firefox) or migrate the manifest to Manifest V3.
```

在拒绝 Manifest V2 的目标上，`start` 和 `preview` 随后会以这条退出信息停止：

```plaintext
Chrome refuses to load this extension, so there is nothing to preview.
PATH /path/to/project/dist/chrome
Read the reason above, fix the manifest, then run the command again.
```

从 4.1.41 之后的版本开始，这条信息的第一行是 `Chrome refuses to load this extension, so nothing in it runs.` 如果浏览器给出了自己的那句话，这条信息会把它放在 `REASON` 一行，并以 `Fix what the browser names, then run the command again.` 结尾。

`dev` 会话在构建警告之后会继续运行。浏览器报告的拒绝会以 `extension_load_refused` 记录在 `ready.json` 里，也会记录在 `extension logs` 里。终端不会再打印第二次。其他原因造成的拒绝仍然会打印。

从 4.1.41 之后的版本开始，Manifest V2 的情况仍然沿用这条规则。它的结论是唯一不等待浏览器的预测。在 `dev` 和 `start` 下由构建警告说出，在 `preview` 下则由上面那一行在启动之前打印。其他每一个预测都会被按住。见[被拒绝的加载会打印什么](#被拒绝的加载会打印什么)。

### 无效的 match 模式

无效的模式位于哪里，决定了浏览器怎么做：

- **`content_scripts[].matches`、`content_scripts[].exclude_matches` 或 `web_accessible_resources[].matches`**：Chrome 拒绝整个扩展。
- **`host_permissions` 或 `optional_host_permissions`**：Chrome 和 Firefox 会加载扩展并丢弃这个模式。这个模式不授予任何 host 访问权限，Chrome 不记录任何错误或警告，列表中的其他模式仍然生效。

host 语法允许 `*`、`*.domain.tld` 或一个字面量 host。host 中任何其他位置的通配符都是无效的，例如 `https://foo.*.com/*`。端口、查询字符串和片段不会触发拒绝，而且端口本身也可以是通配符。

从 4.1.41 之后的版本开始，Extension.js 会打印一条警告，点名每一个被丢弃的模式。它在 `build`、`dev` 和 `start` 期间打印，也在 `preview` 启动之前打印：

```plaintext
manifest.json lists host permission patterns the browser drops, so they grant no host access.
PATTERN https://foo.*.com/* in host_permissions
Chrome and Firefox load the extension, Chrome records no error or warning for it, and the other patterns in the list still apply.
Write the host as *, *.domain.tld or a literal host.
```

### 加载拦截项清单

下面每一项都已在真实的 Chrome 构建上验证过会拒绝整个扩展：

- **`name`**：缺失、为空，或不是字符串。Chrome 要求一个非空的字符串名称。
- **`version`**：缺失，或不是 1 到 4 段以点分隔的整数，且每段取值在 0 到 65535 之间。
- **MV3 的 `web_accessible_resources`**：条目必须是字典，包含 `resources`，外加 `matches`、`extension_ids` 或 `use_dynamic_url` 三者之一。MV2 的字符串数组写法在 MV3 上会被拒绝。MV2 下它仍然合法。
- **`content_scripts` 语法**：`matches` 是必填且不得为空，`js` 与 `css` 的条目必须是字符串，`run_at` 只接受 `document_start`、`document_end` 或 `document_idle`，并且每个条目至少要有一个 `js` 或 `css` 文件。
- **`minimum_chrome_version`**：无效的值会直接被拒绝。取值合法但高于解析出来的浏览器版本同样会被拒绝，因此该检查比对的是这个会话实际启动的那个二进制。
- **`commands`**：Chrome 最多允许 4 个带 `suggested_key` 的快捷键。Firefox 没有上限，所以从 Firefox 移植过来的扩展经常在这里翻车。
- **`key`**：必须是合法的 base64 公钥。padding 有问题就会导致扩展被拒绝。
- **图标**：只要有一个 manifest 图标（`icons.*` 或任意 `*_action.default_icon`）对应的文件缺失或大小为 0 字节，整个扩展就会被拒绝。
- **语言包**：声明了 `default_locale`，但对应的 `_locales/<locale>/messages.json` 缺失或不是合法 JSON，会被拒绝。整串 `__MSG_key__` 引用在目录中没有定义时同样如此（查找不区分大小写，`@@predefined` 名称除外）。`_locales` 目录树里有内容、manifest 中却没有 `default_locale`，也会被拒绝。
- **`storage.managed_schema`**：schema 路径在扩展目录内不存在时，整个扩展会被拒绝。

每一条发现都会在启动之前作为一条警告打印出来，点名扩展路径和每一个拦截项，所以卡住的原因会提前讲清楚。从 4.1.41 之后的版本开始，只有在无法询问浏览器时才会打印这条发现。

## Chromium 会加载的形态

有两种 manifest 形态，你可能以为 Chromium 会拒绝，它却会加载。两者都在 Chrome 151 上实测过。

- **Manifest V3 有 `background.scripts` 而没有 `background.service_worker`**：扩展会被加载，得到一个扩展 ID，并且不显示任何错误。这些脚本永远不会启动。Extension.js 会发出警告并照常启动。
- **大于 3 的 `manifest_version`**：扩展会被加载，并作为 Manifest V3 运行，浏览器不给出任何警告。Firefox 会拒绝它。从 4.1.41 之后的版本开始，Extension.js 的构建在每一个目标上都拒绝不是整数 2 或 3 的 `manifest_version`。

## Firefox 的拒绝

这些结果是在 Firefox Nightly 160 上实测的。

- **只有 `background.service_worker`**：Firefox 拒绝这个扩展。它给出的原因是 `background.service_worker is currently disabled. Add background.scripts.` 面向 Firefox 的 Extension.js 构建会替你写出 `background.scripts`。见[后台脚本](/zh-Hans/docs/implementation-guide/background)。
- **`strict_min_version` 高于正在运行的版本**：以临时附加组件方式加载时，这不算拒绝。
- **Firefox 不加载的 `manifest_version`**：Firefox 的原话不会点名版本。从 4.1.41 之后的版本开始，会有一行 `CAUSE` 指出 manifest 显示的问题。它写的是 `Firefox does not load a manifest_version above 3.` 或 `Firefox loads only the integer 2 or 3 as manifest_version.`

## 构建时的自动修复

其中一部分致命形态足够没有歧义，可以直接修掉。在构建过程中，Extension.js 会在产出的 `manifest.json` 里修复这些：

| 形态                                                        | 修复方式                                                          |
| ----------------------------------------------------------- | ----------------------------------------------------------------- |
| `name` 缺失、为空或不是字符串                               | 把数字和布尔值转成字符串，否则使用 `"Unnamed Extension"`。        |
| `version` 缺失                                              | 注入 `"0.0.0"`。                                                  |
| `version` 是数字（`1.0`）                                   | 转成字符串形式。                                                  |
| `version` 字符串不符合 Chrome 的语法（`"x.y.z"`）           | 抢救出其中的数字部分（`"1.0-beta"` 变成 `"1.0"`），否则用 `"0.0.0"`。 |
| action 上的 `default_icon` 为空（`""` 或 `{}`）             | 删掉这个键。空就意味着没有图标。                                  |
| 图标文件存在但大小为 0 字节                                 | 删掉这条图标条目。                                                |
| `content_security_policy.extension_pages` 的 script-src 里有 `'unsafe-inline'` | 去掉它。MV3 从不认它，所以改变的只是那个拒绝而已。 |
| 具名 command 的 `description` 缺失或为空                    | 回退为该 command 的名称（`_execute_*` 命令除外）。                |

每一次修复都会在发生的那一刻在 CLI 输出中报告一行修复说明，并记录一条 `manifest.json` 构建警告，所以不会有任何东西被悄悄改写。

有些修复只适用于某一个浏览器目标。完整列表请参见[跨浏览器兼容性](/zh-Hans/docs/features/cross-browser-compatibility)。

<Note>
  修复只作用于产出的 `dist` manifest。你的源码 `manifest.json`
  永远不会被修改。看到修复说明时请去修源码，让这次修复不再被需要。
</Note>
