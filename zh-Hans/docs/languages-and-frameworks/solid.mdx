用 Solid 的信号和 JSX 编写扩展界面，不必自己添加构建配置。

Extension.js 会从依赖中检测 Solid。它会把自动 JSX 运行时指向 `solid-js`，并把 `solid-js/jsx-runtime` 解析到工具链自带的一个小适配层。该适配层调用 hyperscript 入口 `solid-js/h`，因为 `solid-js` 发布的是 JSX 类型，而不是 JSX 运行时模块。

<Warning>
  Solid 不属于 Extension.js
  视为一等公民的四个框架。没有 Solid 模板，没有 fast
  refresh，下面的响应式限制也是真实存在的。在新项目里选用 Solid 之前请先读完。
</Warning>

## 什么场景适合用 Solid

- 你已经熟悉 Solid 的信号，想在扩展界面里使用。
- 你要把现有的 Solid 代码迁移到浏览器扩展。
- 你想给 popup、侧边栏或新标签页一个体积很小的运行时。

## 在已有扩展中加入 Solid

没有 `solid` 模板，所以请从其他模板或你自己的项目开始。

### 安装

只需安装一个依赖：

<CodeGroup>

```bash npm
npm install solid-js
```

```bash pnpm
pnpm add solid-js
```

```bash yarn
yarn add solid-js
```

```bash bun
bun add solid-js
```

```bash deno
deno add npm:solid-js
```

</CodeGroup>

Extension.js 会读取 `dependencies` 和 `devDependencies`，放在哪一个里都可以。

### 文件扩展名

Extension.js 根据文件扩展名选择解析器。纯 JavaScript 用 `*.jsx`，TypeScript 用 `*.tsx`。`.ts` 文件永远不会解析 JSX。

### TypeScript 配置

生成的 `tsconfig.json` 会设置 `"jsx": "react-jsx"`，并且没有 JSX 导入源。于是编辑器和 `tsc` 会去找 `react/jsx-runtime`，而 Solid 项目里并没有它。请自己补上导入源：

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "solid-js"
  }
}
```

打包器不读取这个设置，所以没有它构建也会成功。只有类型检查和编辑器提示需要它。

## 构建时发生了什么

Extension.js 用 SWC 编译你的 JSX，使用自动运行时，并把 `solid-js` 作为导入源。它还会把 `solid-js/jsx-runtime` 和 `solid-js/jsx-dev-runtime` 别名到自带的适配层。除此之外没有别的改动，也不会运行任何 Babel 预设。

```tsx
import {render} from "solid-js/web";
import {createSignal} from "solid-js";

function Counter() {
  const [count, setCount] = createSignal(0);

  return (
    <button onClick={() => setCount(count() + 1)}>count {() => count()}</button>
  );
}

const root = document.getElementById("root");

if (root) render(() => <Counter />, root);
```

## 需要预先考虑的响应式限制

Solid 通常用 `babel-preset-solid` 编译 JSX，它会包装每个动态表达式，让 DOM 自行更新。Extension.js 不运行这样的编译器，因此适用的是 hyperscript 的规则。

### 把信号作为函数传入

自动 JSX 运行时只在元素创建的那一刻读取一次 `{count()}`。那个值之后再也不会变。改为传入函数，绑定就会保持响应式：

```jsx
<p>{() => count()}</p>
```

同样的规则适用于属性和控制流。`<Show when={count() > 0}>` 的条件只读取一次，所以需要响应的 `when` 也要写成函数形式。

### 运行时必须只有一份

自带的适配层用 Node 解析方式解析 `solid-js/h`，得到的是 CommonJS 构建产物。而你自己的 `import` 语句解析到的是 ECMAScript 构建产物，于是包里出现了两份 Solid 运行时。在一份里创建的信号，对另一份里的 DOM 绑定是不可见的，什么都不会更新。

把别名指向 ECMAScript 构建产物，两份就会合并成一份：

```js
import {createRequire} from "node:module";

const require = createRequire(import.meta.url);

export default {
  config: (config) => {
    config.resolve = config.resolve || {};
    config.resolve.alias = {
      ...(config.resolve.alias || {}),
      "solid-js/h$": require.resolve("solid-js/h/dist/h.js"),
    };

    return config;
  },
};
```

这个文件是项目根目录下的 `extension.config.js`。别名的值是 `solid-js` 包内部的路径，所以在 Solid 大版本升级后请再确认一次。

### 更新通过 live reload 生效

fast refresh 只覆盖 React 和 Svelte。Solid 的一次改动会重新加载并重新挂载受影响的界面，因此组件状态不会在改动后保留。

## 排查

- **出现关于 `react/jsx-runtime` 的 JSX 报错：** 在 `tsconfig.json` 中加上 `jsxImportSource`。
- **首次渲染正确，之后不再更新：** 加上上面的别名。
- **某个值仍然从不更新：** 写成 `{() => value()}`，而不是 `{value()}`。
- **没有检测到 Solid 集成：** 确认 `package.json` 里有 `solid-js`。
