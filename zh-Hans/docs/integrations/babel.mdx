只有当你需要 SWC（Speedy Web Compiler）覆盖不到的转换或插件时，才引入 Babel。让 SWC 继续作为默认管线，再把 Babel 限定到真正需要它的文件上。

## 什么场景适合用 Babel

- 你依赖 Babel 独有的插件或预设。
- 你正在把一个 Babel 主导的现有项目逐步迁移过来。
- 你想针对特定文件类型（例如 MDX）做有目标的转换。

## Babel 的能力

| 能力                              | 它能带来什么                                                 |
| --------------------------------- | ------------------------------------------------------------ |
| 有针对性的转换                    | 针对特定文件类型（例如 MDX）跑 Babel，而无需替换整条构建管线 |
| 接入插件生态                      | 复用其他 web 项目里 Babel 独有的预设/插件                    |
| 渐进式迁移                        | 把遗留的、重度依赖 Babel 的扩展项目分步迁移到 Extension.js   |
| Rspack（Extension.js 打包器）集成 | 通过 `extension.config.*` 的 `config` 钩子配置 Babel         |

## 示例配置

安装 Babel 依赖：

<CodeGroup>

```bash npm
npm install -D @babel/core @babel/preset-env babel-loader
```

```bash pnpm
pnpm add -D @babel/core @babel/preset-env babel-loader
```

```bash yarn
yarn add -D @babel/core @babel/preset-env babel-loader
```

```bash bun
bun add -d @babel/core @babel/preset-env babel-loader
```

```bash deno
deno add -D npm:@babel/core npm:@babel/preset-env npm:babel-loader
```

</CodeGroup>

创建 `babel.config.json`：

```json
{
  "presets": ["@babel/preset-env"]
}
```

在 `extension.config.js` 里把 Babel 只接到 MDX 上：

```js
export default {
  config: (config) => {
    config.module.rules.push({
      test: /\.mdx$/,
      use: ["babel-loader", "@mdx-js/loader"],
    });
    return config;
  },
};
```

## 你的 Babel 配置在 SWC 之前运行

从 4.2.0 之后的版本起，项目文件夹里的 Babel 配置无需你添加任何规则就会运行。Extension.js 会查找 `babel.config.*`、`.babelrc`、`.babelrc.*` 或 `package.json` 里的 `babel` 键，并让 Babel 先处理每一个项目脚本，但从不处理 `node_modules`。随后 SWC 编译 Babel 的输出，所以 TypeScript、JSX、浏览器目标和 React Refresh 仍由 SWC 负责。你的配置不需要 TypeScript 或 JSX 预设，因为 Extension.js 会给 Babel 读取这些文件所需的语法插件。Extension.js 为此自带 `babel-loader` 和 `@babel/core`。没有 Babel 配置的项目永远不会为脚本加载 Babel。

```json babel.config.json
{
  "plugins": ["babel-plugin-macros"]
}
```

所以前面配置步骤里的 `babel.config.json` 也会作用于项目里的每一个脚本。4.2.0 及之前的版本只通过你添加的规则运行 Babel。

Babel 无法替换 SWC。`config` 里的规则只能添加 loader，不能移除 loader，所以 SWC 仍会在 Babel 之后编译你的脚本。见 [Loader 顺序](/zh-Hans/docs/features/extension-configuration#loader-顺序)。

## 最佳实践

- Babel 配置只放 SWC 缺少的插件，因为它会作用于每一个项目脚本。
- 让 Babel 规则保持显式，以便 loader 顺序可预期。
- 仅在迁移或插件兼容性确有需要时才复用 Babel。
