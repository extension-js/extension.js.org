[chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp) 让 AI agent 直接控制一个运行中的 Chrome 实例。近期版本加入了扩展工具：`install`、`list`、`reload`、`trigger` 和 `uninstall`，以及 service worker 日志。它是 Google 的项目，并不了解你的构建。它可以很好地配合 Extension.js dev 会话使用，后者负责构建、重载和生成的 manifest。

## 它为 dev 会话带来什么

- 驱动任意页面：点击、滚动、填写表单。
- 性能追踪、Lighthouse 审计和网络检查。
- 检查不是你构建的扩展。
- 用真实用户手势触发工具栏 action。

所有涉及你项目的操作仍由 Extension.js 负责：`extension dev` 负责构建和重载，`extension logs`、`extension eval`、`extension storage` 和 `extension open` 负责观察和控制。参见[调试](/zh-Hans/docs/debugging)。

## 手势注意事项

`extension open action` 会在没有用户手势的情况下重放你的 `chrome.action.onClicked` 处理器。它可脚本化、可无头运行，并且在 Chromium 和 Firefox 上都能工作，但它不会授予 `activeTab`。当处理器依赖该授权时，请使用 chrome-devtools-mcp 的 `trigger_extension_action`，它通过 Puppeteer 点击真实按钮。它仅支持 Chromium，并且需要可见窗口。重放机制见[触发 action 与键盘命令](/zh-Hans/docs/debugging/trigger-actions-and-commands)。

<Note>
  chrome-devtools-mcp 的扩展工具（`--categoryExtensions`）需要管道连接。在 Chrome 149 之前，该类别不支持通过 WebSocket 端点附加到已在运行的浏览器。
</Note>

## 与 extension.dev MCP 服务器并用

extension.dev 提供一个 MCP 服务器，把同一个会话以工具的形式暴露给 agent。这些工具以 `extension_*` 为命名空间，因此两个服务器不会冲突。双服务器配置、能力对照表和"该用哪个"表格见 [docs.extension.dev/tools/chrome-devtools-mcp](https://docs.extension.dev/tools/chrome-devtools-mcp)。
