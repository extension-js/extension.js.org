Keep formatting consistent across the extension codebase with minimal manual effort. Prettier runs from scripts, editor integration, and continuous integration (CI). It does not run inside the Extension.js build pipeline.

## When Prettier is a good fit

- You want deterministic formatting in local and CI workflows.
- You are onboarding contributors and need low-friction style consistency.
- You want ESLint to focus on correctness while Prettier handles formatting.

## Prettier capabilities

| Capability                 | What it gives you                                        |
| -------------------------- | -------------------------------------------------------- |
| Consistent formatting      | One shared style for JS, TS, JSON, CSS, and Markdown     |
| Script and editor workflow | Format on save locally and enforce in CI                 |
| Lint conflict reduction    | Pair with `eslint-config-prettier` to avoid rule overlap |
| Low-maintenance defaults   | Adopt a stable baseline with minimal configuration       |

## Template examples

### Prettier configuration template

Preconfigured formatter setup for new projects.

![`new-config-prettier` screenshot](/images/examples/newtab-config-prettier/screenshot.png)

<CodeGroup>

```bash npm
npx extension@latest create my-extension --template=newtab-config-prettier
```

```bash pnpm
pnpx extension@latest create my-extension --template=newtab-config-prettier
```

```bash yarn
yarn dlx extension@latest create my-extension --template=newtab-config-prettier
```

```bash bun
bunx extension@latest create my-extension --template=newtab-config-prettier
```

```bash deno
deno run -A npm:extension@latest create my-extension --template=newtab-config-prettier
```

</CodeGroup>

Repository: [examples/newtab-config-prettier](https://github.com/extension-js/examples/tree/main/examples/newtab-config-prettier)

## Usage with an existing extension

Install Prettier:

<CodeGroup>

```bash npm
npm install -D prettier
```

```bash pnpm
pnpm add -D prettier
```

```bash yarn
yarn add -D prettier
```

```bash bun
bun add -d prettier
```

```bash deno
deno add -D npm:prettier
```

</CodeGroup>

Create a configuration file (for example, `.prettierrc`):

```json
{
  "semi": false,
  "singleQuote": true,
  "trailingComma": "none",
  "printWidth": 80,
  "tabWidth": 2,
  "arrowParens": "always"
}
```

Run Prettier from scripts or manually:

<CodeGroup>

```bash npm
npm run format
```

```bash pnpm
pnpm format
```

```bash yarn
yarn format
```

```bash bun
bun run format
```

```bash deno
deno task format
```

</CodeGroup>

If no format script exists yet:

<CodeGroup>

```bash npm
npx prettier --write .
```

```bash pnpm
pnpm exec prettier --write .
```

```bash yarn
yarn prettier --write .
```

```bash bun
bunx prettier --write .
```

```bash deno
deno run -A npm:prettier --write .
```

</CodeGroup>

## Integration with ESLint

To avoid formatting-rule conflicts in ESLint, install:

<CodeGroup>

```bash npm
npm install -D eslint-config-prettier
```

```bash pnpm
pnpm add -D eslint-config-prettier
```

```bash yarn
yarn add -D eslint-config-prettier
```

```bash bun
bun add -d eslint-config-prettier
```

```bash deno
deno add -D npm:eslint-config-prettier
```

</CodeGroup>

Then add `eslint-config-prettier` in your ESLint configuration chain so ESLint defers formatting concerns to Prettier.

## Best practices

- Keep formatting automatic in editor and CI, not manual.
- Use `--check` in CI and `--write` locally.
- Format staged files pre-commit in larger repositories.
