Keep iteration fast by knowing which changes apply instantly and which require a restart. Extension.js chooses the lightest safe update mode per file change.

## Update modes

| Mode                         | What happens                                                | Typical impact                                            |
| ---------------------------- | ----------------------------------------------------------- | --------------------------------------------------------- |
| Hot module replacement (HMR) | Module/style updates apply in-place                         | Fastest iteration, no full extension relaunch             |
| `Hard reload`                | The target browser reloads the extension runtime            | Extension context restarts, but dev process keeps running |
| Compiler restart             | The session rebuilds its compiler by itself and reloads the extension | Applies entrypoint and list changes with no action from you |
| `Restart required`           | A warning asks you to restart `extension dev`               | Needed only for an edit to `extension.config.*`           |

## Common examples

| Change                                           | Expected behavior                         |
| ------------------------------------------------ | ----------------------------------------- |
| Edit content script/component code               | HMR/remount path (when supported)         |
| Edit style imports used by content scripts/pages | HMR-style update path (context-dependent) |
| Edit `manifest.json` values (non-structural)     | Hard reload flow                          |
| Add/remove manifest entrypoint references        | The session restarts itself               |
| Change script/style entries in an HTML entrypoint | The session restarts itself              |
| Add `pages/` or `scripts/` entrypoints           | The session restarts itself               |
| Delete or rename `pages/` or `scripts/` entrypoints | The session restarts itself, from the release after 4.1.41 |
| Edit `extension.config.*`                        | Restart required                          |
| Edit `_locales/*/messages.json`                  | Hard reload flow                          |

## What to do when you need to restart

One change still needs a restart by you: an edit to `extension.config.*`. The session keeps the config that it read at startup and prints a warning. Stop the session and run `extension dev` again.

A dev session restarts its compiler by itself for a manifest entry change, for a change to the script or style entries of an HTML entrypoint, for an `.env` change, and for a file added under `pages/` or `scripts/`. From the release after 4.1.41, it also does so for a file deleted or renamed there.

## Practical guidance

- Prefer editing existing modules/assets during active dev sessions for fastest feedback.
- Batch structural manifest changes (entrypoint list edits) so the session restarts once.
- Treat restart required diagnostics as authoritative; continuing without restart can leave your runtime in a stale state.
