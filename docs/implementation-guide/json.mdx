Use JSON resources for extension features like rulesets and managed schemas with validation and predictable output handling.

Extension.js processes manifest-referenced JSON resources and validates them for known feature types. It watches them during development and emits output assets when needed.

## JSON capabilities

| Capability                | What it gives you                                                              |
| ------------------------- | ------------------------------------------------------------------------------ |
| Manifest resource support | Handle Declarative Net Request (DNR) rulesets and managed schema files cleanly |
| JSON validation           | Fail early on malformed JSON and invalid resource shape                        |
| Dev dependency tracking   | Recompile when referenced JSON resources change                                |
| Placeholder replacement   | Resolve supported `$EXTENSION_*` placeholders in emitted JSON                  |

## JSON support

Common manifest fields:

| Manifest field                           | File type expected |
| ---------------------------------------- | ------------------ |
| `declarative_net_request.rule_resources` | .json              |
| `storage.managed_schema`                 | .json              |

## Sample JSON declaration in `manifest.json`

Example JSON declaration in `manifest.json`:

```json
{
  "manifest_version": 3,
  "name": "My Extension",
  "version": "1.0.0",
  "declarative_net_request": {
    "rule_resources": [
      {
        "id": "ruleset_1",
        "enabled": true,
        "path": "rules/ruleset.json"
      }
    ]
  },
  "storage": {
    "managed_schema": "schema/storage-schema.json"
  }
}
```

## Output path

Extension.js emits JSON resources by feature context (for example, DNR and storage schema outputs):

```plaintext
declarative_net_request/<ruleset-id>.json
storage/managed_schema.json
```

## Development behavior

- Extension.js tracks manifest-referenced JSON files as file dependencies.
- JSON edits trigger recompilation.
- When a manifest edit adds, removes, or renames a JSON reference, a running `extension dev` session restarts its compiler by itself.

## Validation behavior

Extension.js validates:

- JSON syntax for referenced resources
- DNR ruleset shape (array-based ruleset expectations)
- Managed storage schema shape (object-based expectations)

### Rulesets that Chrome refuses

A Chromium build warns about two `declarativeNetRequest` ruleset shapes. Chrome refuses to load the whole extension over either one, and Firefox loads the same file.

- **A repeated rule id**: two rules in one ruleset share an `id`.
- **A `regexFilter` that Chrome cannot compile**: the filter has a lookahead, a lookbehind, or a backreference.

```plaintext
The Declarative Net Request ruleset listed in declarative_net_request/main uses a rule id more than once, and Chrome refuses to load an extension whose ruleset does.
PATH rules/main.json
RULE id 3
Firefox loads the same ruleset and leaves a rule out. Give every rule in the file its own id.
The build continues.
```

```plaintext
A rule in the Declarative Net Request ruleset listed in declarative_net_request/main has a regexFilter Chrome cannot compile, and Chrome refuses to load an extension whose ruleset has one.
PATH rules/main.json
RULE id 3
REASON the filter uses a lookbehind
Chrome reads the filter as RE2, which has no lookahead, lookbehind or backreference, and Firefox accepts the rule. Rewrite the filter without it.
The build continues.
```

Both are warnings, not errors, because the same file is valid on Firefox. Firefox and Safari builds print nothing.

## Environment placeholders

Extension.js replaces `$EXTENSION_*` placeholders in emitted `.json` assets during compilation, using the same pass as static HTML placeholder replacement.

## Best practices

- Keep manifest-referenced JSON focused on browser-required resource formats.
- Validate JSON resources in continuous integration (CI) before packaging.
- Prefer stable file paths in manifest, because each path change restarts the compiler of the dev session.
- For app data consumed by code, consider JSON imports in JS/TS modules separately from manifest resource JSON.
